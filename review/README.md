## 「なぜ」の記録

仕組みの理由として本文に書き足した説明は、根拠の種類を分けて [why.md](why.md) に記録しています。

## 判定の見方

| 判定 | 意味 |
|---|---|
| 一致 | 仕様書の記述と合っている |
| **修正** | 誤りや古い記述があったので本文を直した |
| **追加** | 仕様書に照らして足りなかった内容を本文に足した |
| 計算を確認 | 本書が仕様の値から計算した数字で、計算を検算した |
| 原本の値 | LE Primer（原本）の値や説明をそのまま使っている |
| 実装の例 | 仕様ではなく、よくある実装の値 |
| 本書の解釈 | 仕様書が理由を述べていない点についての本書の説明 |
| 対象外 | 仕様の外の一般的な知識（名前の由来、電波法など） |
| 未照合 | 仕様書と照合していない（本文か付録で明記している） |

「根拠」の欄の書き方は、本書の第19章と同じです（例：「Vol 6 Part B §4.5.9」「BB §6.7」「ARCH §5.2」）。

## 照合していないもの

- KNOB と BIAS の攻撃の説明（第29章）、出力の等級 Class 1 と 2（第21章）、Wi-Fi のチャネル幅に基づく AFH の計算（第30章）
- 製品によくある動き（第28章、第31章）、用途ごとの使い分けの提案（第31章）
- 実機での動作。この記録はすべて仕様書の文面との照合で、実際の機器では確かめていません

## もう一度照合するには

Core 仕様の HTML 版は、部ごとに1枚のページになっています（例：`.../Core_v7.0/out/en/low-energy-controller/linklayer-ll--specification.html`）。[tools/html2txt.cjs](tools/html2txt.cjs) は、保存したページから本文だけを取り出して文字にするスクリプトです。節の見出しの番号が残るので、`grep` で記述を探せます。

```bash
node tools/html2txt.cjs <HTML を保存したフォルダ>
```
