# 第9章 5階建ての運び道

::: goal
- 物理チャネルから L2CAP チャネルまでの5つの階層を、下から順に言える
- 階層とパケットの欄の対応を説明できる
- 5つの物理チャネルと、5つの論理トランスポートの役割を説明できる
- データの性質から、適切な運び道を選べる
:::

ここは Architecture 編の中心の話題です。Classic のデータの通り道は、5つの階層に積み重なっています。名前が多くて最初は戸惑うかもしれませんが、この章の地図があれば第10章以降の話がすっきり整理できます。

::: analogy 宅配便
1階の物理チャネルは**道路網**です。2階の物理リンクは、ある倉庫と特定の取引先を結ぶ**配送契約**。3階の論理トランスポートは**サービスの種類**で、「確実に届ける宅配便」と「決まった時刻に走る定期便」では、運び方が違います。4階の論理リンクは**荷物の分類**（社内連絡か、お客さまの荷物か）。5階の L2CAP チャネルは、荷物の**宛先の部署**です。
:::

なぜ「論理リンク」と「論理トランスポート」を分けるのか、不思議に思うかもしれません。これには歴史的な事情があります。ACL と SCO はそれぞれ独立した接続のように振る舞うのですが、実は LT_ADDR や再送のしくみを共有していて、完全には切り離せません。この絡み合いを記述するために、運び方の階を別に設けたのです。ARCH §3 も「効率と過去との互換のため」と説明しています。

## 9.2 階とパケットの対応

この階層を理解するには、パケットのどの欄がどの階の札になっているかを見るのが一番です。

| 階 | 見分ける札 | 場所 |
|---|---|---|
| 1 物理チャネル | アクセスコードと周波数の列 | パケットの先頭 |
| 2 物理リンク | **札がない**。論理トランスポートから逆算する | ― |
| 3 論理トランスポート | LT_ADDR と TYPE | ヘッダ |
| 4 論理リンク | LLID | ペイロードヘッダ |
| 5 L2CAP チャネル | CID | L2CAP のヘッダ |

面白いのは2階です。物理リンクには名札がありません。1つの論理トランスポートは必ず1つの物理リンクの上にあるので、LT_ADDR を見れば物理リンクも自動的に決まるからです。

逆に言えば、パケットは**必要な階の分の欄しか持ちません**。Inquiry の ID パケットはアクセスコードだけです。論理リンクも何もない段階の呼びかけだからです。SCO のパケットには、ペイロードヘッダがありません。

## 9.3 1階：物理チャネル

物理チャネルは、「どの周波数の列を、どの時計で、どの合言葉で使うか」の組み合わせです。Classic には5種類あります。

| 物理チャネル | 用途 | 周波数 | 合言葉 | 時計 |
|---|---|---|---|---|
| 基本ピコネット | 接続中の通信 | 79本すべて | Central のアドレスから | Central |
| 適応ピコネット | 接続中の通信（AFH） | 20本以上 | Central のアドレスから | Central |
| Inquiry Scan | 発見 | 32本 | 全機器共通 | 聞く側 |
| Page Scan | 接続 | 32本 | 聞く側のアドレスから | 聞く側 |
| 同期スキャン | CPB の受信の準備 | 3本（固定） | Central のアドレスから | Central |

大事な制約があります。**1台の機器が同時に使える物理チャネルは1つだけ**です（仕様はそう仮定しています）。ヘッドホンを Peripheral として使いながら Page Scan もできるのは、時分割で行き来しているからです。

基本と適応のピコネットチャネルは、時計も合言葉も同じで、スロットもそろっています。AFH については[第16章](./ch16)で見ます。

## 9.4 2階：物理リンク

ピコネットの物理チャネルの上に、Central と Peripheral の組ごとに物理リンクができます。

| 物理リンク | 向き | 特徴 |
|---|---|---|
| Active | 双方向、1対1 | 送信電力の設定や、Hold と Sniff のモードはこの階の性質 |
| CPB | 片方向、1対多 | 返事がないので電力の調整はできない |

Inquiry や Page の最中にも一瞬のリンクがあると考えることはできますが、設定を変えたりはできないので、あまり意味はありません。

Sniff などの省電力モード（[第12章](./ch12)）は、この物理リンクの「いつ居るか」を変える話です。

## 9.5 3階：論理トランスポート

データの**運び方**を決める階です。次の3つの問いで分類できます。

| 問い | 選択肢 |
|---|---|
| **誰に？**（キャスト） | 1対1（ユニキャスト）／ 全員（ブロードキャスト） |
| **いつ？**（時間の扱い） | 同期（予約した時間に一定量）／ 非同期（空いているときに）／ アイソクロナス（期限つき） |
| **何を？**（データの分類） | 制御／ L2CAP のデータ／ ストリーム／ 定期放送 |

Classic の論理トランスポートは5つです。

| 名前 | 運ぶもの | 向き | 信頼性 |
|---|---|---|---|
| **ACL** | データ全般と LMP | 双方向、1対1 | 再送あり（期限を付けることも可） |
| **SCO** | 64 kb/s の音声 | 双方向、1対1 | 再送なし |
| **eSCO** | 一定レートのストリーム | 双方向、1対1（非対称も可） | 限られた再送あり |
| **APB** | 全員宛ての L2CAP と LMP | 片方向 | 確認なし（繰り返して補う） |
| **CPB** | 定期放送 | 片方向、台数無制限 | 確認なし |

ACL は Asynchronous Connection-oriented の略、SCO は Synchronous Connection-Oriented の略です。古い資料には ACL を Asynchronous Connection-Less（接続なし）と書いたものもありますが、今の仕様では connection-oriented です。

Peripheral はピコネットに入るとすぐ、**デフォルト ACL** という ACL を1本受け取ります。SCO や eSCO は必要になってから追加します。デフォルト ACL を切ると、その相手との他の論理トランスポートも全部なくなります。接続の土台なのです。

## 9.6 4階：論理リンク

1つの論理トランスポートに、種類の違う荷物を混ぜて運べます。

| 論理リンク | 載る論理トランスポート | 内容 | LLID |
|---|---|---|---|
| ACL-C | ACL | LMP | `0b11` |
| ACL-U | ACL | L2CAP のデータ | `0b10`（先頭）／ `0b01`（続き） |
| APB-C | APB | 全員宛ての LMP | `0b11` |
| APB-U | APB | 全員宛ての L2CAP | `0b10` ／ `0b01` |
| SCO-S | SCO | ストリーム | なし |
| eSCO-S | eSCO | ストリーム | なし |
| PBD | CPB | 定期放送 | `0b10` |

名前の末尾には規則があります。**C** は Control、**U** は User、**S** は Stream です。

SCO や eSCO は1種類のストリームしか運ばず、長さも決まっているので、LLID もペイロードヘッダも要りません。

ACL-C（LMP）はチップどうしの内部の会話なので、ホストからは見えません。同じトランスポートの ACL-U より優先されます。

接続が成立した直後には、ACL-C、ACL-U、APB-C、APB-U の4本が自動で揃います。

## 9.7 5階：L2CAP チャネル

ACL-U の上で、L2CAP がさらに通路を分けます。ACL-U は1本でも、音楽の通路、リモコンの通路、SDP の通路を同時に作れます。L2CAP については[第13章](./ch13)で詳しく見ます。

分かれ目になるのは**フレームが必要かどうか**です。

- **フレームつき**：「この塊で1つ」という区切りのあるデータ。L2CAP が大きさの違う塊を運び、相手にも同じ塊として届ける
- **フレームなし**：区切りのない一定の流れ。L2CAP を通さず、SCO や eSCO に直接流し込む

レートが変わるアイソクロナスのデータ（たとえば圧縮した音楽）は、SCO や eSCO には載せられません。この2つはパケットの大きさと周期が固定だからです。そこで ACL を「期限つき」に設定して運びます。音楽が eSCO ではなく ACL で運ばれるのは、この理由によります（[第10章](./ch10)）。

::: se
TCP/IP の層と1対1には対応しませんが、次のように考えると少し分かりやすくなります。1階と2階は L1 と L2 の間にあたり、3階は TCP と UDP の選択に似た「運び方の選択」を、もっと低い層で行うものです。5階の CID はポート番号に近いものです。ただし無理に対応させず、Classic 独自の整理として覚えるほうが結局は早いでしょう。
:::

## まとめ

- データの通り道は、物理チャネル、物理リンク、論理トランスポート、論理リンク、L2CAP チャネルの5階建てである
- 札は下から順に、アクセスコード、（なし）、LT_ADDR と TYPE、LLID、CID である
- 物理チャネルは5種類あり、1台の機器は同時に1つしか使えない
- 論理トランスポートは ACL、SCO、eSCO、APB、CPB の5種類で、運び方が違う
- 論理リンクの末尾の C、U、S は制御、ユーザー、ストリームを表す
- フレームが必要なデータは L2CAP と ACL で、一定の流れは SCO や eSCO で運ぶ

## 確認問題

1. 物理リンクに名札がなくても困らないのは、なぜでしょうか。
2. SCO のパケットにペイロードヘッダが要らないのは、なぜでしょうか。
3. 次のデータは、どの論理リンクで運ぶのが自然でしょうか。(a) 写真の転送、(b) 通話の音声、(c) 2台のチップの間の暗号化の設定の交渉
4. デフォルト ACL を切断すると、その相手との eSCO はどうなるでしょうか。

::: details 答え
1. 論理トランスポートは必ず1つの物理リンクの上にあるので、LT_ADDR が分かれば物理リンクも決まるからです。
2. 運ぶのは1種類のストリームだけで、長さも周期も接続時に決まっているので、LLID も長さも要らないからです。
3. (a) ACL-U（L2CAP）、(b) eSCO-S または SCO-S、(c) ACL-C（LMP）です。
4. 一緒になくなります。デフォルト ACL は他の論理トランスポートの土台です。
:::
