# 第28章 プロファイル

::: goal
- プロファイルが何を定めるものかを説明できる
- GAP を土台としたプロファイルの階層を説明できる
- A2DP、HFP、SPP、HID が、それぞれどのプロトコルの上にあるかを言える
- 音楽と通話で別のプロファイルを使う理由を説明できる
:::

コア仕様が用意したのは、運び道（ACL、eSCO、L2CAP）と、検索の手段（SDP）までです。その上で「音楽を聴く」「電話に出る」を実現するのが**プロファイル**です。この章の後半は Core 仕様の外の話が中心です。

## 28.1 プロファイルとは

2台の機器が L2CAP でつながっても、同じ言葉で話さなければ音は鳴りません。音の形式は？再生の開始の合図は？プロファイルは、ある用途のために**スタックの全体をどう使うかを決めた取り決め**です。

Architecture 編の説明を整理すると、プロファイルは次のものを定めます。

- 各層で必須の機能（PHY から L2CAP、さらに上のプロトコルまで）
- 層と層の間の縦の関係、2台の同じ層どうしの横の関係
- アプリの動作とデータの形式
- サービス検索の要件（SDP に何を書くか）

2台の機器が同じプロファイルの要件を満たしていれば、メーカーが違っても動きます。

::: analogy
L2CAP までは「道路と配送の決まり」です。プロファイルは「レストランのデリバリーでは、この順番で注文し、この容器で運び、玄関でこう受け渡す」という**業界の取り決め**です。お店（メーカー）が違っても、同じ取り決めなら客（別のメーカーの機器）は困りません。
:::

## 28.3 主なプロファイル

::: extra コア仕様の外からの補足
ここからの内容は、Core 仕様の外の各プロファイルの仕様書に書かれています。公式の Assigned Numbers で確認できた番号（UUID、PSM）以外は、一般的な解説や実装の資料に基づくもので、プロファイルの仕様書そのものとは照合していません。正確な定義は各プロファイルの仕様書にあたってください。
:::

| プロファイル | 用途 | 主なプロトコル | サービスの UUID の例 |
|---|---|---|---|
| A2DP | 音楽の配信 | AVDTP | `0x110A`（Source）, `0x110B`（Sink） |
| AVRCP | 再生の操作、音量など | AVCTP | `0x110C`（Target）, `0x110E` |
| HFP | ハンズフリー通話 | RFCOMM、eSCO | `0x111E`（HF）, `0x111F`（AG） |
| HSP | 簡易なヘッドセット | RFCOMM、eSCO | `0x1108` |
| SPP | シリアルポートの代わり | RFCOMM | `0x1101` |
| HID | キーボード、マウス | HID プロトコル | `0x1124` |
| OPP | ファイルの送受信 | OBEX、RFCOMM | `0x1105` |
| PBAP | 電話帳の転送 | OBEX | `0x112F`（Server） |
| MAP | メッセージの転送 | OBEX | `0x1132`（Server） |

### RFCOMM：線を作る

RFCOMM は、L2CAP の上に**シリアルポートのような通信路**を作るプロトコルです（PSM `0x0003`）。Bluetooth の出発点が「ケーブルの置き換え」だったことが、ここによく現れています。もともとは携帯電話の規格 TS 07.10 を元にしています。

サービスはサーバチャネル番号（1〜30）で区別します。番号は SDP で調べます（[第27章](./ch27)）。

アプリから見ると、ソケットを開いてバイト列を流すだけの単純な通路です。TCP に近い感覚で使えるので、開発ボードと PC の通信などで今も広く使われています。

### A2DP：音楽を流す

**A2DP**（Advanced Audio Distribution Profile）は、音楽を片方向に流すプロファイルです。送る側を **Source**（スマホ）、受ける側を **Sink**（ヘッドホン）と呼びます。**AVDTP** というプロトコルの上で動き、L2CAP のチャネルを2本使います。

| チャネル | 流れるもの |
|---|---|
| シグナリング | コーデックの交渉、開始、停止 |
| メディア | 音楽のデータそのもの |

どちらも PSM `0x0019` です。始めるまでの流れはおおむね次のとおりです。

A2DP に対応する機器が必ず実装するコーデックが **SBC** です。音質を上げたい場合は、両者が対応していれば AAC や、メーカー独自のコーデックも使えます。Source と Sink は GET_CAPABILITIES の結果から、共通に使える中で最もよいものを選びます。

**どれくらいの帯域を使うのか**、代表的な設定で計算してみましょう。SBC の一般的な高音質の設定は、ステレオで 328 kb/s です。3-DH5（1021 バイト）で運ぶと、

<div class="formula">328,000 ビット/秒 ÷ (1021 × 8 ビット) ≒ 40 パケット/秒<br>40 × 6 スロット ＝ 240 スロット ＝ 1600 の 15%</div>

上の層のヘッダを無視すれば、電波の時間の15%ほどです。残りは再送や他の機器に使えます。これだけ余裕があるので、電波の状況が悪くても再送で乗り切れます。

### AVRCP：操作を送る

再生、一時停止、音量の操作は別のプロファイルの **AVRCP** が担当します。ヘッドホンのボタンを押すと、コマンドが **AVCTP**（PSM `0x0017`）で流れていきます。A2DP がデータを、AVRCP が操作をと、役割を分けています。

### HFP：電話に出る

**HFP**（Hands-Free Profile）は通話のプロファイルです。役割は **AG**（Audio Gateway、スマホ）と **HF**（Hands-Free、ヘッドホンやカーナビ）です。

特徴は、**制御と声が別の道を通る**ことです。

| | 通り道 | 内容 |
|---|---|---|
| 制御 | RFCOMM の上の AT コマンド | 着信、応答、電話番号の通知など |
| 声 | eSCO（または SCO） | L2CAP を通らない |

AT コマンドは、電話回線のモデムの時代からある文字のコマンドです。`AT+BRSF` で機能を確認し合い、`RING` で着信を知らせます。40年以上前に生まれた形式が、今のイヤホンの中で動いているのは楽しい話です。

通話の音質は、順に次のように拡張されてきました。

| コーデック | サンプリング | 呼び方 | 備考 |
|---|---|---|---|
| CVSD | 8 kHz | 狭帯域 | HFP の必須 |
| mSBC | 16 kHz | 広帯域 | Wide Band Speech |
| LC3 | 32 kHz | 超広帯域 | 新しい版の HFP で追加。LE Audio と同じコーデック |

### HID：入力機器

キーボードやマウスは **HID**（Human Interface Device）プロファイルを使います。USB の HID と同じ考え方のレポートを、L2CAP の2本のチャネルで運びます。

| PSM | 用途 |
|---|---|
| `0x0011` | 制御（設定など） |
| `0x0013` | 割り込み（キー入力など） |

ふだんは Sniff で眠っていて（[第26章](./ch26)）、入力があると短い間隔でデータを流します。

## 28.4 同時に使う

実際のヘッドホンは A2DP、AVRCP、HFP を同時に使います。

- 音楽を聴いているときは A2DP が流れ、AVRCP と HFP は待機している
- 着信があると、HFP の RFCOMM で知らせが来る
- 電話に出ると eSCO が立ち上がり、A2DP は一時停止する

通話中に音質ががらりと変わるのは、この切り替えのためです。音楽用の A2DP は片方向なので、マイクの音を送り返せません。マイクを使うには HFP の eSCO に切り替える必要があるのです。音質は通話用のコーデックの水準に下がります。

LE Audio は、この「2つの世界」を1つのしくみにまとめることを目標の1つにしています（[第9章](./ch09)）。

::: bio
プロファイルの階層は、代謝経路の共通の部分に似ています。解糖系のような共通の経路を土台にして、細胞ごとに必要な枝を足していく。すべてのプロファイルが GAP を土台にして、用途の枝を足していくのと同じです。
:::

::: spec
- **ARCH §6.1〜6.3**：プロファイル、GAP、階層の説明（本章の前半）
- **ARCH §6.4〜6.5**：GATT ベースのプロファイルの階層。本書では LE 編で扱った
- **GAP**：GAP の全要件
- Core 仕様の外：[Bluetooth SIG の仕様書の一覧](https://www.bluetooth.com/specifications/specs/)に、各プロファイルの仕様書がある
:::

## まとめ

- プロファイルは、ある用途のためのスタックの使い方の取り決めである
- GAP を土台に、汎用のプロファイル、アプリケーションプロファイルと積み重ねる
- Classic では、プロファイルごとに使うプロトコルが違う
- A2DP は AVDTP の上で音楽を流し、AVRCP は操作を、HFP は RFCOMM と eSCO で通話を担当する
- HFP では制御と声が別の道を通る
- 音楽と通話を切り替えると、プロファイルごと切り替わるので音質が変わる

## 確認問題

1. A2DP の SBC の 328 kb/s を 2-DH5（679 バイト）で運ぶと、1600 スロットの何パーセントを使うでしょうか。上の層のヘッダは無視します。
2. 通話の声はどの運び道を通るでしょうか。L2CAP を通るでしょうか。
3. ヘッドホンで音楽を聴きながら音声アシスタントを起動すると音質が変わります。なぜでしょうか。
4. スマホのアプリと開発ボードの間でバイト列を簡単に流したいとき、どのプロファイルが手軽でしょうか。

::: details 答え
1. 328,000 ÷ (679 × 8) ≒ 60.4 パケット/秒です。1パケットで6スロット使うので 362 スロット、1600 の約 23% です。
2. eSCO（または SCO）を通ります。L2CAP は通りません。
3. マイクの音を送り返すには HFP の eSCO が必要で、A2DP から切り替わるからです。
4. SPP です。RFCOMM の上で、ソケットのようにバイト列を流せます。
:::
