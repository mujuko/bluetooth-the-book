# 第21章 電波とパケット

::: goal
- BR と EDR の変調の違いを説明できる
- Classic のパケットの構造を図に描ける
- DH5 や 3-DH5 のような名前から、パケットの性質を読み取れる
- パケットの種類から最大の速さを計算できる
:::

ピコネットのリズムが分かったので、今度は1つのスロットの中で電波に何を乗せているかを見ます。

## 21.1 79本のチャネル

Classic は LE と同じ 2.4 GHz 帯を使います。チャネルの周波数は単純な式で決まっています。

<div class="formula">周波数 ＝ 2402 ＋ k MHz（k ＝ 0, 1, …, 78）</div>

1 MHz 間隔で 79 本です。LE は 2 MHz 間隔の 40 本なので、Classic のほうが細かく区切られています（LE のチャネルの図は[第4章](./ch04)）。

## 21.2 BR と EDR：1回の変化に何ビット乗せるか

Classic の変調のシンボルレートは、どのモードでも **1 Msym/s** です。1秒に100万回、波の状態を変えます。違うのは、1回の変化に何ビット乗せるかです。

| モード | 変調 | 1シンボルのビット数 | 電波の速さ |
|---|---|---|---|
| BR | GFSK | 1 | 1 Mb/s |
| EDR（2M） | π/4-DQPSK | 2 | 2 Mb/s |
| EDR（3M） | 8DPSK | 3 | 3 Mb/s |

GFSK は周波数を上下にずらす方式でした（[第4章](./ch04)）。上か下かの2択なので、1回に1ビットです。

EDR は**位相**の変化で情報を伝えます。位相とは、波の1周期の中の位置を角度で表したものです。「時計の針が、前のシンボルから何度回ったか」をイメージしてください。回り方が4通りなら2ビット、8通りなら3ビットを表せます。

名前の D は Differential（差分）です。絶対的な角度ではなく、**前のシンボルからの変化**に情報を乗せます。これなら、受信機が波の絶対的な位相を知らなくてもよくなります。

::: deep なぜシンボルレートを上げないのか
LE の 2M PHY は、シンボルレートを2倍にして速くしました。その代わりチャネル幅は 2 MHz あります。Classic のチャネルは 1 MHz なので、シンボルレートを上げると隣のチャネルにはみ出します。そこで、シンボルレートはそのままで、1シンボルの情報量を増やす道を選びました。

代償もあります。選択肢が増えると隣の選択肢との角度の差が小さくなるので、雑音で読み違えやすくなります。一般に、3 Mb/s のパケットは 2 Mb/s より弱い電波に弱い傾向があります。
:::

::: extra コア仕様の外からの補足：出力の等級
製品の説明で「Class 1」「Class 2」という言葉を見かけることがあります。Class 1 が最大 100 mW（20 dBm）、Class 2 が最大 2.5 mW（4 dBm）で、Class 2 の到達距離はおよそ 10 m とよく説明されます。Core v7.0 の無線の編を確認したところ、この等級の表は見当たらなかったので、ここでは従来の資料での呼び方として紹介するにとどめます。
:::

## 21.3 パケットの形

BR のパケットは、基本的に3つの部分でできています。EDR は途中で変調を切り替えるので、切り替えのための部分が加わります。

**アクセスコード**は「どの物理チャネルの会話か」を示す札で、すべてのパケットの先頭にあります。プリアンブル 4 ビット、同期ワード 64 ビット、トレーラ 4 ビットの計 72 ビットです。同期ワードはアドレスの LAP から作られ、受信機は届いた信号を手持ちのパターンと照合します。一致すれば「自分たちのパケットだ」と分かり、同時に時間のずれも測れます。

アクセスコードには3種類あり、場面によって使い分けます。

| 種類 | もとになるもの | 使う場面 |
|---|---|---|
| CAC（チャネル） | Central の LAP | 接続中のすべてのパケット |
| DAC（デバイス） | 呼び出す相手の LAP | Page のとき |
| IAC（Inquiry） | 予約された LAP | Inquiry のとき |

### ヘッダ

ヘッダは**接続の交通整理の情報**で、18 ビットです。ただし無線の上では、各ビットを3回ずつ繰り返して 54 ビットで送ります。多数決で誤りを直せるようにするためです（符号化率 1/3 の FEC）。

| 欄 | 役目 |
|---|---|
| LT_ADDR | 誰宛てか、誰からか（[第20章](./ch20)） |
| TYPE | パケットの種類。何スロットを占めるかも分かる |
| FLOW | 「受信バッファがいっぱいだから止めて」（[第24章](./ch24)） |
| ARQN | 前のパケットが届いたかどうかの返事（[第24章](./ch24)） |
| SEQN | 再送かどうかを見分ける番号（[第24章](./ch24)） |
| HEC | ヘッダの誤りの検出。合わなければパケットごと捨てる |

TYPE の値で占めるスロット数が分かるので、自分宛てではない Peripheral は、そのパケットが終わるまで受信機を止められます。わずかですが節電になります。

ヘッダだけをこれほど厳重に守っているのは、ヘッダが壊れるとパケット全体が読めないうえ、次に誰が話すかも分からなくなるからです。

::: bio
ヘッダの「3回繰り返し」は、重要な遺伝子を複数コピー持つ冗長性に似ています。1か所に変異が入っても、残りのコピーで機能を保てます。
:::

### ペイロードヘッダ

ACL のパケット（[第24章](./ch24)）のペイロードには、さらに小さなヘッダがあります。

| 欄 | ビット数 | 役目 |
|---|---|---|
| LLID | 2 | LMP か L2CAP か。L2CAP なら先頭か続きか |
| FLOW | 1 | L2CAP レベルの流量調整 |
| LENGTH | 5 または 10 | 本体の長さ |

`LLID` は[第23章](./ch23)でまた登場します。

## 21.4 パケットの種類

Classic のパケットの名前には規則があります。

| 記号 | 意味 |
|---|---|
| D | Data（データ用、ACL で使う） |
| M | Medium：FEC あり（符号化率 2/3）。誤りに強いが運べる量は減る |
| H | High：FEC なし。誤りに弱いが量が多い |
| 1, 3, 5 | 占めるスロット数 |
| 先頭の 2- / 3- | EDR の 2 Mb/s / 3 Mb/s |

読み方の例を挙げます。

- **DM1**：データ用、FEC あり、1スロット。一番堅実で、LMP の制御メッセージにも使う
- **DH5**：データ用、FEC なし、5スロット。BR で一番速い
- **3-DH5**：データ用、3 Mb/s、5スロット。Classic で一番速い

EDR のパケットには、FEC を付けない D**H** しかありません。

| 種類 | 本体の最大（バイト） | FEC | スロット | 片方向の最大（kb/s） | 逆方向（kb/s） | 両方向で均等のとき（kb/s） |
|---|---:|---|---:|---:|---:|---:|
| DM1 | 17 | 2/3 | 1 | 108.8 | 108.8 | 108.8 |
| DH1 | 27 | なし | 1 | 172.8 | 172.8 | 172.8 |
| DM3 | 121 | 2/3 | 3 | 387.2 | 54.4 | 258.1 |
| DH3 | 183 | なし | 3 | 585.6 | 86.4 | 390.4 |
| DM5 | 224 | 2/3 | 5 | 477.8 | 36.3 | 286.7 |
| DH5 | 339 | なし | 5 | **723.2** | 57.6 | 433.9 |
| 2-DH1 | 54 | なし | 1 | 345.6 | 345.6 | 345.6 |
| 2-DH3 | 367 | なし | 3 | 1174.4 | 172.8 | 782.9 |
| 2-DH5 | 679 | なし | 5 | 1448.5 | 115.2 | 869.1 |
| 3-DH1 | 83 | なし | 1 | 531.2 | 531.2 | 531.2 |
| 3-DH3 | 552 | なし | 3 | 1766.4 | 265.6 | 1177.6 |
| 3-DH5 | 1021 | なし | 5 | **2178.1** | 177.1 | 1306.9 |

この表の数字は、自分で計算できます。DH5 で片方向に流し続ける場合を考えましょう。Central は5スロットのパケットを送り、Peripheral は短い1スロットの返事を返します。つまり6スロットで1周です。

<div class="formula">339 バイト × 8 ＝ 2712 ビット、6 スロット ＝ 3.75 ms<br>2712 ビット ÷ 3.75 ms ＝ 723.2 kb/s</div>

逆方向の 57.6 kb/s は、返事のスロットに DH1 のデータ（27 バイト）を載せたときの値です。両方向とも DH5 にすると10スロットで1周するので、片方向あたり 2712 ÷ 6.25 ms = 433.9 kb/s になります。

「3 Mb/s と言うわりに 2.18 Mb/s しか出ない」のは、ヘッダ、切り替えの時間、返事のスロットがあるからです。さらに上の層のヘッダも引かれるので、アプリから見える値はもう少し下がります。

::: deep 仕様書の中の小さな違い
Architecture 編（ARCH §1）は BR を 721.2 kb/s、EDR を 2.1 Mb/s と紹介しています。一方、ベースバンド編（BB §6.7）の表では DH5 が 723.2 kb/s、3-DH5 が 2178.1 kb/s です。本書は計算で再現できるベースバンド編の値を使います。「BR はおよそ 0.7 Mb/s、EDR はおよそ 2.1 Mb/s」と覚えておけば、実用上は十分です。
:::

### FEC ありとなし、どちらを選ぶか

DM5 は DH5 より運べる量が少ないのに、なぜ必要なのでしょう。

電波の状態がよければ、FEC は無駄です。でも状態が悪いと、FEC なしのパケットは少しの誤りで再送になります。長いパケットほど、途中で壊れる確率は上がります。そんなときは、短いパケットや FEC ありのパケットのほうが、再送が減って結果的に速くなります。

そこでコントローラは、電波の状況に応じてパケットの種類を選び直します。使ってよい種類は、リンクマネージャどうしの交渉で決まります（[第26章](./ch26)）。

### 制御用のパケット

データを運ばない、特別なパケットもあります。

| 種類 | 長さ | 用途 |
|---|---:|---|
| ID | 68 ビット | アクセスコードだけの最短のパケット。Inquiry と Page で使う |
| NULL | 126 ビット | 返事の代わり。ARQN や FLOW の情報だけ伝える |
| POLL | 126 ビット | NULL と同じ形だが、Peripheral に返事を要求する |
| FHS | 366 ビット | 自分のアドレスと時計の値を相手に伝える |

NULL と POLL の 126 ビットは、アクセスコード 72 ＋ ヘッダ 54 です。FHS の 366 ビットは、これに 240 ビットのペイロードを足した値です。

音声用の HV、EV で始まるパケットは[第25章](./ch25)で扱います。

::: spec
- **RF §3、§4**：送信と受信の性能の要件。受信感度の基準は −70 dBm、BER 0.1%
- **BB §6.3.3**：同期ワードの作り方（LAP に符号をかけ、疑似雑音を重ねる）
- **BB §7.1、§7.2**：HEC と CRC の生成、データのホワイトニング
- **BB §7.4、§7.5**：FEC の詳細（1/3 は単純な繰り返し、2/3 は短縮ハミング符号）
- **BB §6.5.2.4**：データと音声を1つのパケットに混ぜる DV パケット
- **ARCH §3.2.1**：パケットの各部分と階層の関係の説明。本書では第23章で扱う
:::

## まとめ

- チャネルは 2402 ＋ k MHz（k ＝ 0〜78）の 79 本で、幅は 1 MHz
- シンボルレートは常に 1 Msym/s で、1シンボルのビット数が BR は1、EDR は2または3である
- パケットはアクセスコード、ヘッダ、ペイロードからなる。EDR はヘッダまで GFSK で送り、途中で変調を切り替える
- ヘッダは18ビットで、3回繰り返して送る
- 名前の DM / DH、スロット数、2- / 3- でパケットの性質が分かる
- 最大の速さは「本体のビット数 ÷ 1周のスロット時間」で計算できる

## 確認問題

1. 3-DH3 は、1シンボルに何ビット乗せ、何スロットを占めますか。FEC はありますか。
2. 2-DH5 の片方向の最大の速さを、本体の最大長から計算してください。返事は1スロットとします。
3. EDR のパケットで、ヘッダまでを GFSK で送るのはなぜだと思いますか。
4. 電波の状態が悪いときに DH5 より DM3 のほうが速いことがあるのは、なぜでしょうか。

::: details 答え
1. 3ビット、3スロット、FEC なしです。
2. 679 × 8 = 5432 ビットです。1周は6スロットで 3.75 ms なので、5432 ÷ 3.75 ms ≒ 1448.5 kb/s です。
3. 同じピコネットに EDR に対応していない機器がいても、ヘッダを読めば自分宛てでないと判断できるからです。また、ヘッダの TYPE や LT_ADDR を読んで初めて、続きが EDR かどうかが分かります。
4. 長くて FEC のないパケットは、少しの誤りでも全部を再送することになるからです。短くて FEC のあるパケットなら、誤りを直せる場合があり、壊れても失う量が少なくて済みます。
:::
