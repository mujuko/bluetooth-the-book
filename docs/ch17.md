## 17.2 場面ごとに層を追う

### 場面0：電源を入れる

ヘッドホンの電源が入ります。ペアリングした相手がいないので、ペアリングモードに入り、**Inquiry Scan** と **Page Scan** をオンにします（[第8章](./ch08)）。コントローラは短い窓を定期的に開いて耳を澄まし、ほかの時間は眠っています。

SDP のサーバには、A2DP Sink、HFP、AVRCP のサービスレコードが用意されています（[第13章](./ch13)）。

### 場面1：探す

ユーザーがスマホの設定画面を開きます。OS は HCI で `HCI_Inquiry` を発行し、スマホのコントローラは 3200 回/秒の速さで ID パケットを撃ち始めます。

ヘッドホンの受信機がいる周波数に ID が届くと、625 µs 後に FHS で返事をし、続けて EIR で「○○ Headphones」という名前と対応サービスを伝えます。スマホは名前とアイコンを画面に出します（[第7章](./ch07)、[第8章](./ch08)）。

### 場面2：つなぐ

ユーザーがタップします。スマホはヘッドホンのアドレスから DAC と周波数の列を計算し、FHS で知った時計の値から相手の周波数を予測して、Page を始めます。

FHS を受け取ったヘッドホンは、スマホの時計に合わせるオフセットを計算します。そしてスマホのアドレスに基づく周波数の列へ移ります。これで**ピコネット**ができました。Page したスマホが Central です（[第6章](./ch06)）。

同時に、デフォルト ACL と、ACL-C、ACL-U、APB-C、APB-U の論理リンクができあがります（[第9章](./ch09)）。

### 場面3：チップどうしの交渉

2台のリンクマネージャが LMP で対応機能を確かめ合います。EDR に対応しているか、AFH に対応しているか。どの長さのパケットを使ってよいか（[第12章](./ch12)）。

### 場面4：調べる

スマホの OS は L2CAP のチャネルを開いて（PSM `0x0001`）、SDP で問い合わせます。ヘッドホンは「A2DP Sink は L2CAP の PSM `0x0019` の AVDTP で使える」と答えます。HFP についても「RFCOMM のチャネル○番」と答えます（[第13章](./ch13)）。

### 場面5：ペアリング

ヘッドホンには画面がないので、入出力の能力の交換の結果は Just Works です。公開鍵を交換し、確認の値をやり取りし、リンクキーを計算して保存します（ボンディング）。次にそのリンクキーで認証し、暗号化を始めます（[第15章](./ch15)）。

スマホはヘッドホンをペアリング済みの機器として覚えます。ヘッドホンも Inquiry Scan をオフにします。

### 場面6：音楽のチャネル

AVDTP のシグナリングで、ヘッドホンの対応コーデックを確かめて SBC に決めます。続いてメディア用の L2CAP チャネルを開きます（[第14章](./ch14)）。

### 場面7：音が届く

ここが第II部のクライマックスです。アプリが「再生」を押しました。

**スマホ（送信）**

1. OS が音を SBC で圧縮する。A2DP が推奨する高音質の設定では、128 サンプルを 119 バイトのフレームにする（44.1 kHz で約 2.9 ms 分）
2. SBC のフレームをまとめて（ここでは5個で 595 バイト）、SBC のヘッダ 1 バイト、AVDTP のメディアパケットのヘッダ 12 バイトを付ける（608 バイト）
3. L2CAP のヘッダ 4 バイトを付ける（612 バイト、CID はヘッドホンのメディアチャネル）
4. HCI で「自動フラッシュしてよい」と指定して、コントローラへ渡す

**コントローラ（送信）**

5. ベースバンドが 2-DH5（最大 679 バイト）を選ぶ。ペイロードヘッダの LLID は `0b10`、長さ 612
6. CRC、暗号化（AES-CCM なら MIC も）を付ける
7. Central の順番（偶数スロット）が来るのを待つ
8. アクセスコードとヘッダを GFSK で、ペイロードを π/4-DQPSK で送る。5スロット分（約 3.1 ms）の枠に収まる

**電波**

9. 79 本（または AFH で減らした本数）のうちの1本で、約 3 ナノ秒でヘッドホンに届く

**ヘッドホン（受信）**

10. アクセスコードが一致するので「自分たちのピコネット」と判断する
11. ヘッダの LT_ADDR が自分宛てで、TYPE で 2-DH5 と分かる。途中で変調を切り替える
12. CRC を確かめ、暗号を解き、次のスロットで ARQN=ACK を返す
13. LLID を見て L2CAP を組み立て、HCI でホストへ渡す
14. L2CAP が CID を見て AVDTP に渡し、SBC のフレームを取り出す
15. デコードして再生のバッファへ入れる

約 3.75 ms（6スロット）で、約 14.5 ms 分の音が届きました。そのあとは次のパケットが来るまで、電波の時間には余裕があります。

<div class="formula">電波の時間：3.75 ms ÷ 14.5 ms ≒ 26%</div>

残りの時間で再送したり、別の機器と話したりできます。

### 場面8：邪魔が入ったら

近くの Wi-Fi が混んできました。パケットが壊れて CRC が合わず、ヘッドホンは ARQN=NAK を返します。スマホは同じデータを次の機会に別の周波数で再送します（[第10章](./ch10)）。

失敗が多いチャネルは、スマホの判断で AFH のマップから外されます（[第16章](./ch16)）。

再送が間に合わないほど状況が悪いと、期限が切れて**フラッシュ**され、音がプツッと途切れます。電波の状況によっては、コントローラが 3M より頑丈な 2M や BR のパケットに切り替えることもあります。

### 場面9：電話がかかってくる

着信です。HFP の RFCOMM のチャネルで、AT コマンドの `RING` がヘッドホンに届きます。ユーザーがボタンを押すと応答します。

スマホは A2DP を一時停止し、LMP で **eSCO** を追加します。スロットが予約され、Central と Peripheral はたとえば 12 スロットごとに 2-EV3 で声をやり取りするようになります（[第11章](./ch11)）。音質は通話の水準に変わります。

電話を切ると eSCO は解放され、A2DP がまた始まります。

### 場面10：止める、別れる

音楽を止めてしばらくすると、ホストの判断で **Sniff** に入ります。たとえば数百ミリ秒ごとにしか聞かなくなり、ヘッドホンの電池の消費が減ります（[第12章](./ch12)）。

電源を切ると、LMP で切断を伝えてピコネットを解散します。圏外に出たなら、リンクスーパービジョンタイムアウトの後に切断とみなされます（[第10章](./ch10)）。

次にヘッドホンの電源を入れると、Inquiry なしで Page だけでつながり、ペアリングの確認もなしに音楽が始まります。

## 17.4 Classic を振り返る

Classic の物語を振り返ると、1本の筋が見えてきます。

**すべてはピコネットの時計から始まります**。Central の時計とアドレスが、周波数の跳び方、合言葉、話す順番を決めます。あとはこの共通のリズムの上に、用途の違うデータの運び方を積み重ねただけです。確実に届けたいなら ACL の再送、遅れてほしくないなら eSCO の予約、という選択があるだけです。

Classic は「いかに流し続けるか」の技術でした。次の第III部では、正反対の「いかに眠るか」という発想から生まれた LE を見ていきます。ランナーの胸の心拍計が主役です。

実物を観察する方法は第31章で紹介します。ヘッドホンをつないだときの HCI のログを Wireshark で開けば、この章の流れがそのまま文字として並んでいるのが見えるはずです。

## 最後の確認問題

1. 場面7で、Peripheral はどうやって「この 2-DH5 の後半は π/4-DQPSK だ」と知るのでしょうか。
2. 場面7の L2CAP のフレームが 700 バイトになると、2-DH5 では何パケット必要でしょうか。2個目のパケットの LLID は何でしょうか。
3. 場面9で eSCO を始める前に A2DP を止めるのは、なぜだと思いますか。
4. 次回の接続で Inquiry が要らない理由と、ペアリングが要らない理由をそれぞれ答えてください。

::: details 答え
1. ヘッダの LT_ADDR と TYPE を GFSK のまま読みます。この接続で EDR が有効になっていることは LMP で交渉済みなので、TYPE の値から 2-DH5 だと分かり、切り替えの部分の後は π/4-DQPSK で受信します。
2. 700 ÷ 679 = 1.03… なので 2 パケットです。2個目は続きなので LLID は `0b01` です。
3. 通話中は音楽を再生しないのが普通だからです。また、音楽のデータを止めれば、そのぶんの電波の時間を通話と再送に回せます。
4. アドレスを覚えているので Inquiry は不要です。リンクキーを保存している（ボンディング）のでペアリングも不要です。
:::
