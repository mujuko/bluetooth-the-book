# 第16章 セキュリティ

::: goal

## 16.1 セキュリティは道具箱

LE のセキュリティ機能のほとんどは任意です。規格は機能を用意するだけで、どれを使うかは製品の設計者が決めます。原本はこれを「道具箱」にたとえています。買った瞬間に安全になるものではなく、**「何から何を守りたいか」を考えて選ぶ**ものです。

考えるべき脅威は、おもに次の4つです。

| 脅威 | 内容 | 対策の例 |
|---|---|---|
| 盗聴 | 電波を傍受して内容を読む | 暗号化 |
| 改ざん | 通信の内容を書き換える | MIC |
| なりすまし・中間者攻撃 | 本物の機器のふりをして割り込む | 認証つきのペアリング |
| 追跡 | 電波を手がかりに人の動きを追う | プライベートアドレス |

## 16.2 ペアリングとボンディング

この2つの言葉はよく混同されます。

- **ペアリング**：2台で暗号の鍵を作る手続き
- **ボンディング**：作った鍵を保存して、次回も使えるようにすること

ボンディングをしない場合、鍵はその接続が終われば使えなくなり、再接続のたびにペアリングが必要です。ボンディングをしていれば、再接続の時は保存した鍵ですぐに暗号化を始められます。ユーザーが毎回操作しなくて済むのはこのためです。

::: bio
免疫にたとえると分かりやすいでしょう。ペアリングは初めての抗原に対する応答で、手間と時間がかかります。ボンディングは免疫記憶で、2回目以降は記憶細胞のおかげで素早く応答できます。
:::

### 盗聴者の前で秘密を共有する

フェーズ2は暗号の面白いところです。2台はまだ何の秘密も共有していません。そして電波は誰でも聞けます。それなのに、盗聴者の目の前で共通の秘密を作るというのです。これを可能にするのが、Core 4.2 で導入された **LE Secure Connections** が使う**楕円曲線ディフィー・ヘルマン鍵共有**です。

::: analogy 絵の具の混色
AさんとBさんが、共通の色の絵の具を決めます（公開情報）。それぞれ、自分だけの秘密の色を混ぜて、混ぜた後の色を相手に送ります。受け取った相手は、そこに自分の秘密の色をさらに混ぜます。すると両者の手元には、同じ「共通色＋Aの秘密＋Bの秘密」の色ができます。盗聴者は混ぜた後の色しか見ていません。絵の具は混ぜるのは簡単ですが、分離するのは困難なので、秘密の色は分かりません。
:::

Bluetooth 4.0 からの古い **LE レガシーペアリング**にはこの仕組みがなく、やり取りを録音されると鍵を解読されてしまう場合があります。新しい製品では Secure Connections を使いましょう。

## 16.4 相手を確かめる：4つの方式

鍵の共有だけでは、まだ不十分です。話している相手が本物である保証がないからです。攻撃者が間に入って、それぞれと別々に鍵を共有する攻撃（**中間者攻撃**、MITM）が考えられます。

これを防ぐには、無線以外の方法で確かめる必要があります。LE には次の方式があり、フェーズ1で教え合った**入出力の能力**に基づいて選ばれます。

| 方式 | ユーザーの操作 | 中間者攻撃への耐性 | 必要な能力 |
|---|---|---|---|
| **Numeric Comparison** | 両方の画面に出た6桁の数字が同じか確認する | あり | 両方に画面と「はい／いいえ」（Secure Connections のみ） |
| **Passkey Entry** | 片方に出た6桁の数字をもう片方に入力する | あり | 片方に画面、もう片方に入力手段 |
| **Out of Band（OOB）** | NFC など無線以外の経路で情報を交換する | 経路の安全性による | 別の経路 |
| **Just Works** | 何もしない | **なし** | なし |

画面もボタンもない心拍計では、Just Works しか選べません。Just Works でも Secure Connections なら盗聴には強いのですが、ペアリングの瞬間に割り込まれると防げません。「暗号化された」と「相手を確認した」は別の話です。

## 16.5 暗号化で守れるもの、守れないもの

ペアリングが終わると、リンク層はパケットを **AES-CCM** で暗号化できます。第5章で見た MIC（4バイト）もここで働き、改ざんを検知します。

ただし、次の点に注意してください。

- **アドバタイズは守られない**：接続の暗号化は接続の中の話です。普通のアドバタイズは誰でも読めます。秘密のデータをアドバタイズに入れてはいけません
- **守られるのは無線の区間だけ**：相手のスマホの中で受け取った後は対象外です。クラウドまで守りたいなら、アプリの層で別に暗号化します

## 16.6 データの保護：パーミッションとの連携

第13章のアトリビュートのパーミッションで、「暗号化された接続でないと読めない」などの条件を設定できます。条件を満たさないアクセスに対して、サーバはエラーを返します（Insufficient Authentication など）。多くのスマホの OS は、このエラーを受けてペアリングの画面を自動で表示します。

GAP はこうした保護の強さを、**セキュリティモードとレベル**として定義しています。接続の暗号化に関わるモード1のレベルは次のとおりです。

| レベル | 内容 |
|---|---|
| 1 | セキュリティなし |
| 2 | 認証なしのペアリングと暗号化（Just Works など） |
| 3 | 認証ありのペアリングと暗号化 |
| 4 | 認証ありの LE Secure Connections と、128ビット鍵の暗号化 |

ほかに、BIG の放送を守るモード3（第9章の Broadcast Code）と、Core 7.0 で加わったモード4があります。モード4はペアリングをせずに接続を暗号化するためのもので、鍵（TAK）の作り方は上位の仕様が決めます。かつてのモード2はデータ署名のためのもので、署名とともに Core 6.3 で廃止されました。

## 16.7 プライバシー：追跡を防ぐ

機器の識別番号である**アドレス**は48ビットで、アドバタイズに入っています。もし固定なら、街中に受信機を置くだけで、特定の人の動きを追跡できてしまいます。そこで LE には複数の種類のアドレスがあります。

| アドレスの種類 | 性質 |
|---|---|
| パブリック | メーカーが取得した世界で唯一の番号。固定 |
| ランダム静的 | 電源投入時などに乱数で作る。動作中は固定 |
| リゾルバブルプライベート（RPA） | 定期的に変わる。鍵を持つ相手だけが正体を分かる |
| ノンリゾルバブルプライベート | 定期的に変わる。誰にも分からない |

**RPA** が巧妙です。アドレスを「乱数の部分」と「その乱数と秘密の鍵から計算した値」で作ります。この鍵が **IRK**（Identity Resolving Key）で、ボンディングのときに配られます。

- IRK を持つ相手：乱数と IRK から計算して一致すれば「知っている機器だ」と分かる
- IRK を持たない第三者：毎回違う番号に見えるので、同じ機器だと分からない

GAP は、アドレスを変える間隔を最長15分にするよう勧めています。Core 6.1 では、更新の間隔をランダムにする機能が加わりました。

::: bio
病原体が表面の抗原を次々に変えて免疫から逃れる「抗原変異」に似ています。ただし RPA では、鍵を持つ相手にだけは見破れるようにしてあります。特定の相手の抗体だけが反応する変異、というイメージです。
:::

## 16.8 新しい保護の機能

他の章に登場した保護機能も挙げておきます。

- **BIG の暗号化**（第9章）：放送は合言葉（Broadcast Code）で守る
- **Channel Sounding の防御**（第10章）：距離の偽装を防ぐ
- **Encrypted Advertising Data**（Core 5.4）：アドバタイズのデータの暗号化
- **Encryption Key Schedule**（Core 7.0）：暗号化を始めるたびにコントローラどうしで新しい公開鍵を交換し、そこから接続や CIS ごとの鍵を段階的に作る

## 16.9 よくある誤解

| 誤解 | 実際 |
|---|---|
| ペアリングしていれば安全 | 方式による。Just Works は中間者攻撃を防げない |
| 非発見モードなら見つからない | パケットは誰でも受信できる（第15章） |
| 距離が短いから盗聴されない | 高利得のアンテナを使えば、ずっと遠くから受信できる |
| 暗号化すれば全部守られる | 守られるのは無線の区間の接続の中だけ |
| RSSI で近さを確かめれば安全 | 強い電波を出せば簡単に偽装できる（第10章） |

## まとめ

- セキュリティ機能は道具箱で、脅威に応じて選ぶ
- ペアリングは鍵を作り、ボンディングは鍵を保存する
- LE Secure Connections は盗聴に強い。中間者攻撃の防止には無線以外の確認が必要
- Just Works は暗号化はするが、相手の確認はしない
- 暗号化は接続の無線の区間を守るだけで、アドバタイズは対象外
- RPA は第三者の追跡を防ぎつつ、鍵を持つ相手には正体を分からせる

## 確認問題

1. 画面もボタンもない温度計と、スマホのペアリングで選ばれる方式は何でしょうか。その弱点は何でしょうか。
2. 再接続のたびにペアリングの操作が必要になる機器があります。何が足りないと考えられるでしょうか。
3. ビーコンのアドバタイズに個人の健康データを入れて、接続なしで配る設計はなぜ問題なのでしょうか。
4. RPA を使っても、IRK を共有した相手は機器を識別できるのはなぜでしょうか。

::: details 答え
1. Just Works です。ペアリングの瞬間に割り込む中間者攻撃を防げません。
2. ボンディング（鍵の保存）が行われていないと考えられます。
3. 通常のアドバタイズは暗号化されず、誰でも受信できるからです。
4. アドレスに含まれる乱数と IRK から値を計算し、アドレスの残りの部分と一致するかを調べられるからです。
:::
