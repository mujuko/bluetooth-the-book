Classic のコントローラは、LE のリンク層に比べると内部でずいぶん多くの判断をしています。この章では、**チップどうしが交わす会話**である LMP と、それが可能にする省電力を見ていきます。

**資源マネージャ**は、電波の時間を配る係です。データ通信、Inquiry、Page、スキャン、別のピコネットとの行き来など、全部が同じ1つの無線を取り合います。スケジューラはこの要求を調整します。音声のように「必ずこの時間が必要」という要求には、前もって約束（アクセス契約）を与えます。

::: analogy
1本の線路を、特急（音声）、普通列車（データ）、検査車両（スキャン）が共用しているようなものです。資源マネージャはダイヤを組む係です。特急のダイヤを先に確保し、残りに普通列車を入れます。
:::

## 12.2 LMP：チップどうしの会話

**LMP**（Link Manager Protocol）は、2台のリンクマネージャが交わすプロトコルです。ACL-C の論理リンクに載り、基本的に信頼性の高い DM1 パケットで運ばれます。**ホストを介さず、チップどうしで完結します**。ホストから見れば、「Sniff に入って」と HCI でお願いすれば、裏で交渉してくれて、結果がイベントで返ってきます。

LMP で交渉する内容の例を挙げます。

| 分類 | 内容 | PDU の例 |
|---|---|---|
| 接続の準備 | 版、対応機能、機器名の問い合わせ | `LMP_FEATURES_REQ`, `LMP_NAME_REQ` |
| 接続の確立 | ホストの了承 | `LMP_HOST_CONNECTION_REQ`, `LMP_SETUP_COMPLETE` |
| パケット | 使ってよいスロット数 | `LMP_MAX_SLOT` |
| 省電力 | Sniff のパラメータ | `LMP_SNIFF_REQ` |
| 音声 | SCO、eSCO の追加 | （[第11章](./ch11)） |
| 役割 | 役割の交代 | `LMP_SWITCH_REQ` |
| 電力 | 送信電力の増減 | `LMP_POWER_CONTROL_REQ` |
| 周波数 | AFH のマップの更新 | `LMP_SET_AFH` |
| 安全 | ペアリング、認証、暗号化 | （[第15章](./ch15)） |

### Sniff：定期的に顔を出す

**Sniff** は最もよく使われる省電力のモードです。Central と Peripheral は、**決まった間隔 Tsniff ごとの時刻（アンカーポイント）にだけ会う**と約束します。LE のコネクション間隔によく似ています。

- Peripheral はアンカーポイントで数スロット（Nsniff attempt）だけ聞く
- 通信があれば、Nsniff timeout の間は聞き続ける
- 通信がなければ、次のアンカーポイントまで眠れる、または別の物理チャネルに行ける

間隔は最大 40.9 秒まで設定できます。

計算例を見てみましょう。Tsniff を 500 ms（800 スロット）にして、そのつど 5 ms だけ聞くとすると、

<div class="formula">5 ms ÷ 500 ms ＝ 1%</div>

Active では、Central が話す可能性のある 800 回／秒のスロットを毎回チェックしていました。受信の時間が大幅に減るのが分かります。

ただし、Sniff には代償があります。**データはアンカーポイントまで待たされる**ので遅れます。キーボードやマウスのように「普段は静かで、ときどき動く」機器、音楽を止めている間のヘッドホンなどで使います。データが流れ始めたらホストの判断で Active に戻します。

SCO と eSCO は Sniff の影響を受けません。論理トランスポートのうち影響を受けるのは ACL だけです。

**Sniff サブレーティング**は、さらに間隔を伸ばすしくみです。ホストが許容できる最大の遅れを指定しておけば、LMP でいちいち交渉し直さずにアンカーポイントを間引けます。データが来たら自動で元の間隔に戻るので、入ったり出たりの手間がかかりません。

### Hold：一度だけ留守にする

**Hold** は「これから○○の間、居ません」と約束する1回限りのモードです。時間が来たら目を覚まして復帰します。Inquiry やスキャン、別のピコネットとの通信のための時間を作るのに使えます。SCO や eSCO の予約のスロットには、Hold の間も出席します。

### 消えたモード：Park

古い資料には **Park** というモードも登場します。Peripheral が LT_ADDR を手放して眠り、7台の枠を空けるというものでした。Core 5.0 で削除されました。今も仕様に「[This section is no longer used]」という節が残っているのは、この名残です。

## 12.4 役割の交代

[第8章](./ch08)で見たように、Page をした側が Central になります。でも、これが不都合なことがあります。

**例1**：スマホがキーボードの Central になっているとします。ここでヘッドホンがスマホへ Page すると、ヘッドホンが Central のピコネットができます。スマホは Central と Peripheral を兼ねることになり、スキャッタネットの負担を抱えます。

**例2**：スマホは自分が Central で全員を束ねるほうが、スケジュールを1か所で管理できます。

そこで、接続の後で**役割を交換**できます。これが**役割の交代**（role switch）です。

ピコネットは Central の時計とアドレスで決まるのでしたから、役割の交代は単に名前を入れ替えるだけではありません。次の2段階の引っ越しです。

1. **TDD の交代**：今の周波数の列のまま、話す順番（偶数と奇数）を入れ替える
2. **ピコネットの交代**：新しい Central の時計とアドレスに基づく物理チャネルへ移る。FHS で新しい Central の情報を伝える

引っ越しには制約があります。

- Sniff や Hold の間、また SCO や eSCO があるときは行えない
- 暗号化をしているなら、いったん止める
- デフォルト ACL だけが移る。ほかの論理トランスポートは上の層が作り直す
- LT_ADDR は変わるかもしれない
- QoS の約束は引き継がれない。交渉し直す

だから多くの実装は、接続の直後、音声などを始める前に役割の交代を行います。図12-2 で「必要なら役割の交代」と書いたのはこのためです。

## 12.5 送信電力の調整

相手の受信状況に応じて、送信電力を増減するしくみもあります。受信側が RSSI（受信の強さ）を見て、「もう少し上げて（下げて）」と LMP で伝えます。

| 方式 | できること |
|---|---|
| 従来の方式 | 1段階ずつ増やす、減らす |
| 拡張された方式 | さらに「最大にして」と頼める。結果も変調ごとに返せる |

電力を必要な分だけ使えば、電池が節約でき、ほかの通信への干渉も減ります。電力は物理リンクの向きごとの性質で、Central は相手ごとに適切な値を使います。ただし、複数の相手への放送では全員に届く値にします。返事のない CPB では、そもそも調整できません。

## 12.6 HCI との対応

ホストから見たときのコマンドとイベントをまとめます。

| 操作 | コマンド | 結果のイベント |
|---|---|---|
| Sniff に入る | `HCI_Sniff_Mode` | `HCI_Mode_Change` |
| Sniff を出る | `HCI_Exit_Sniff_Mode` | `HCI_Mode_Change` |
| 役割の交代 | `HCI_Switch_Role` | `HCI_Role_Change` |
| 音声の追加 | `HCI_Setup_Synchronous_Connection` | `HCI_Synchronous_Connection_Complete` |
| 切断 | `HCI_Disconnect` | `HCI_Disconnection_Complete` |

コマンドの向こう側で、それぞれ LMP の交渉が走っています。

## まとめ

- コントローラの中では、デバイスマネージャ、リンクマネージャ、資源マネージャが協力し、1つの無線の時間を分け合っている
- LMP は ACL-C に載るチップどうしの会話で、ホストからは見えない
- Sniff は定期的なアンカーポイントでだけ会う省電力のモードで、遅れと引き換えに電力を減らす
- Hold は1回限りの留守である。Park は Core 5.0 で削除された
- 役割の交代はピコネットそのものを作り直す引っ越しで、音声などを始める前に行う

## 確認問題

1. LMP のメッセージをアプリから直接読むことができないのはなぜでしょうか。
2. Tsniff が 1 秒のマウスで、ボタンを押したときの最大の遅れはおよそどのくらいでしょうか。実際のマウスで Sniff の間隔を短くするのはなぜでしょうか。
3. ヘッドホンのほうから再接続してヘッドホンが Central になった場合、スマホが役割の交代を望むのはなぜでしょうか。
4. eSCO で通話している最中に、役割の交代はできるでしょうか。

::: details 答え
1. LMP はチップどうしが ACL-C で交わす会話で、ホストの HCI の上には出てこないからです。
2. およそ 1 秒です。使っているときに反応が悪いと困るので、短くするか、Active に戻します。
3. スマホがほかの機器の Central でもある場合、別々のピコネットを行き来するスキャッタネットになるので、自分が Central になって1つにまとめたいからです。
4. できません。同期の論理トランスポートがあるときは役割の交代はできません。
:::
