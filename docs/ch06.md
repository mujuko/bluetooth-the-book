# 第6章 ピコネットと時計

::: goal
- ピコネットが「1つの時計に全員が合わせた集団」であることを説明できる
- 625 µs のスロットで Central と Peripheral が交互に話す様子を図に描ける
- Peripheral が最大7台である理由と、呼ばれないと話せない理由を説明できる
- スキャッタネットとは何かを説明できる
:::

ここから第II部です。第1章のランナーのスマホとヘッドホンを例に、Classic のしくみを下の層から見ていきます。

Classic を理解する一番の近道は、**ピコネット**という集団のイメージをつかむことです。第II部の残りの話は、すべてこの上に積み上がります。

## 6.1 ピコネット

ピコネットは、1台の **Central** と、それにつながる **Peripheral** たちの集団です。スマートフォンとヘッドホンなら、たいていスマートフォンが Central、ヘッドホンが Peripheral になります。

::: extra 古い呼び名
古い資料では、Central と Peripheral は **Master** と **Slave** と書かれています。Core 5.3 で呼び名が改められました。第9章で出てくる APB と CPB も、以前は ASB、CSB（S は Slave）と呼ばれていました。ネット上の解説やソースコードの多くは今も古い名前を使っています。
:::

ピコネットのメンバーは、次の3つを完全に共有します。

- **時計**：Central の時計に全員が合わせる
- **周波数の跳び方**：Central のアドレスと時計から決まるパターンで、全員が同時に跳ぶ
- **合言葉**：Central のアドレスから作ったアクセスコードを、すべてのパケットの先頭に付ける

この3つが1組になったものが、ピコネットの通り道です。仕様ではこれを**物理チャネル**と呼びます。

::: analogy ダンスの一座
ピコネットは、1人の振付師（Central）と踊り手たち（Peripheral）の一座のようなものです。79の部屋がある建物の中を、一座は振付師の手拍子に合わせて全員で部屋を移ります。次の部屋の順番は、振付師の名前と今の拍の番号から全員が同じ計算で求めます。

ほかの一座も同じ建物の中を移動していますが、順番が違うので、ときどき同じ部屋で鉢合わせる程度です。
:::

## 6.2 アドレス

すべての Classic 機器は、48ビットの **BD_ADDR**（Bluetooth Device Address）を持っています。Wi-Fi の MAC アドレスと同じ仕組みで割り当てられる、世界で1つの番号です。3つの部分に分かれ、それぞれに役目があります。

|---|---|
| LAP（下位） | アクセスコードのもとになる |

LE にはアドレスを定期的に変える RPA がありますが（[第30章](./ch30)）、Classic のアドレスは基本的に固定です。そのため、Classic では「むやみに発見可能にならない」ことがプライバシーの要になります（[第8章](./ch08)）。

## 6.3 Bluetooth の時計

どの機器も、独立に動き続ける時計を持っています。**28ビットのカウンタ**で、1目盛りは 312.5 µs です。

<div class="formula">2<sup>28</sup> × 312.5 µs ≒ 83,886 秒 ≒ 23.3 時間</div>

約1日で一周します。ただし時刻とは無関係で、値には意味がありません。大事なのは「今、何拍目か」だけです。

最初の目盛り 312.5 µs の2倍が、Classic の基本単位 **625 µs のスロット**です。1秒は1600スロットになります。

Peripheral は自分の時計の値を書き換えません。代わりに「Central の時計は、自分の時計に**この値を足したもの**」というオフセットを覚えます。これで、自分の時計を動かしたまま Central の時計を計算できます。

なぜ書き換えないのでしょうか。6.7節で見るように、1台の Peripheral が複数のピコネットに参加することがあるからです。ピコネットごとに Central の時計は違うので、自分の時計は動かしたまま、相手ごとに別のオフセットを覚えておくほうが都合がよいのです。

ところが、水晶の精度には限りがあるので、時計は少しずつずれます。通常の動作で許される誤差は **±20 ppm**（100万分の20）です。

<div class="formula">1秒あたり 1,000,000 µs × 20 ÷ 1,000,000 ＝ 20 µs のずれ</div>

そこで Peripheral は、Central のパケットが届くたびにタイミングを微調整します。

::: bio
概日リズムによく似ています。細胞の時計はそれぞれ自走していて（自由継続周期）、視交叉上核のような中枢の時計や光の刺激に**同調**します。Peripheral の時計も自走し続け、Central のパケットという刺激で位相を合わせ直します。長く刺激がなければ、少しずつずれていきます。
:::

## 6.4 スロットと交代

Central と Peripheral は、スロットごとに交代で話します。**時分割複信（TDD）** です（TDD そのものの説明は[第4章](./ch04)）。

- Central は**偶数番**のスロットで話し始める
- Peripheral は**奇数番**のスロットで話し始める
- スロットごとに周波数が変わる。最高で1秒に1600回跳ぶ

1スロットのパケットでも、625 µs を丸ごと使うわけではありません。最も長い場合で 366 µs ほど（72＋54＋240 ビット）で、残りは受信機の準備と周波数の切り替えの時間です。

長いデータのために、**1つのパケットが3スロットや5スロットにまたがる**こともできます。この間は周波数を変えません。パケットが終わると、次の周波数は「今のスロット番号」で計算するので、途中の分を飛ばしたところから続きます。

## 6.5 呼ばれた者だけが話す

Classic のピコネットには、衝突を防ぐ単純なルールがあります。

<div class="formula">Peripheral は、直前の Central のパケットで自分が呼ばれたときだけ、話してよい</div>

呼び出しに使うのが、パケットのヘッダにある **LT_ADDR**（論理トランスポートアドレス）です。Central が Peripheral を迎え入れるときに割り当てる、3ビットの番号です。

<div class="formula">3ビットで8通り − 全員宛ての 000 ＝ 最大 7 台</div>

これが「同時に活発に通信できる Peripheral は最大7台」の理由です。eSCO（[第11章](./ch11)）や CPB も LT_ADDR を1つ消費するので、そのぶん枠は減ります。

話すことがなくても、Central は定期的に Peripheral を呼びます。データのない小さなパケットで、**POLL**（返事を要求する）と **NULL**（返事の代わりに状況だけ伝える）があります。これを**ポーリング**と呼びます。Peripheral どうしが直接話すことはありません。必ず Central を介します。

ここで、Classic が電力を使う理由が見えてきました。

既定の状態（Active）の Peripheral は、**いつ呼ばれるか分からない**ので、Central が話し始める可能性のあるスロットごとに受信機を動かします。データがなくても、最低限ヘッダまでは聞く必要があります。1秒に800回です。電話の例で言うと「受話器を耳に当てたまま」の状態です。これを和らげるしくみは[第12章](./ch12)で見ます。

::: se
USB のホストや RS-485 のマスタによるポーリングと同じ構造です。バスに衝突がない代わりに、スループットとレイテンシをマスタのスケジューラが一手に握ります。CSMA/CD のような衝突の検出や回避はありません。
:::

## 6.6 ホッピング

Classic は 79 本のチャネルを跳びます。順番は、Central のアドレスと時計から計算する疑似乱数です。

::: extra コア仕様の外からの補足：なぜ79本なのか
Bluetooth が設計された1990年代の終わりごろ、米国の規則（FCC Part 15.247）は、2.4 GHz 帯で周波数ホッピングをする無線に、75本以上のチャネルを使うことを求めていました。2400〜2483.5 MHz に 1 MHz 幅で並べると、両端の余白を除いて79本が収まり、この条件を満たします。今の規則では最低の本数は15本になり、75本以上を使うと送信出力の上限が高くなる、という形で残っています。
:::

近くに別のピコネットがあっても、パターンが違うのでたいていはぶつかりません。ぶつかっても1スロット分で、次のスロットにはもう別の周波数にいます。パケットが壊れれば再送します（[第10章](./ch10)）。ピコネットが増えると衝突も増えますが、ある台数で急に通信できなくなるのではなく、性能がなだらかに落ちていきます。

別のピコネットのパケットがたまたま耳に入っても、先頭のアクセスコードが違うので、受信機はすぐに無視できます。

Wi-Fi のように同じ周波数に居座る相手には、**適応ホッピング（AFH）** で、使う周波数を避けます（[第16章](./ch16)）。

ここには2つのルールがあります。

1. **Peripheral としてなら、いくつのピコネットにも参加できる**
2. **Central になれるのは1つのピコネットだけ**

2つ目の理由は定義から明らかです。ピコネットは「Central の時計とアドレス」で決まります。同じ機器が Central なら時計もアドレスも同じなので、別のピコネットを作ろうとしても同じものになってしまいます。

スキャッタネットは、データを中継してくれるわけではないことにも注意してください。コア仕様に経路制御はなく、図のキーボードの入力がカーナビへ届くようなことは起きません。また、行き来している間はどちらかのピコネットを留守にするので、スループットは落ちます。

::: spec
- **BB §2.2.5**：送受信のタイミングの細かい許容範囲
- **BB §2.6**：ホッピングの周波数を求める計算（選択カーネル）。加算、XOR、並べ替えの段からなる
- **BB §1.1**：時計の4種類（CLKR, CLKN, CLKE, CLK）の関係
- **ARCH §3.3.1.1**、**§4.1.1**：基本ピコネットチャネルとトポロジの説明
:::

## まとめ

- ピコネットは1台の Central と Peripheral たちの集団で、時計、跳び方、合言葉を共有する
- 基本単位は 625 µs のスロットで、Central は偶数番、Peripheral は奇数番から話し始める
- Peripheral は呼ばれたときだけ話す。LT_ADDR が3ビットなので Active な相手は最大7台
- Active の Peripheral は呼ばれる可能性のあるスロットを毎回聞くので、電力を使う
- 複数のピコネットに参加するとスキャッタネットになる。Central になれるのは1つだけ

## 確認問題

1. スロットは1秒にいくつありますか。また、スロットのペア（Central と Peripheral の1往復）は何ミリ秒でしょうか。
2. ±20 ppm の時計が2台あると、最悪の場合、1秒でお互いに何マイクロ秒ずれるでしょうか。
3. Peripheral が Central と無関係に勝手に話し始めないのは、なぜでしょうか。
4. スマートフォンが、すでに Central であるピコネットを持ちながら、別の機器の Peripheral になることはできますか。逆に、Central を2つ兼ねることはできますか。

::: details 答え
1. 1 ÷ 0.000625 = 1600 個です。ペアは 2 × 625 µs = 1.25 ms です。
2. それぞれが逆方向に 20 µs ずれると、合わせて 40 µs です。
3. 直前のスロットで自分の LT_ADDR が呼ばれたときだけ話してよいというルールがあるからです。
4. 前者はできます（スキャッタネット）。後者はできません。ピコネットは Central の時計とアドレスで決まるので、同じ機器が Central なら1つのピコネットにしかなりません。
:::
