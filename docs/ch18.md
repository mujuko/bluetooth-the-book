ここから第III部です。第II部の Classic は、つないでいる間データを流し続ける技術でした。Active な Peripheral は、呼ばれるかもしれないスロットを1秒に800回聞いていました（第6章）。

2010年の Core 4.0 で加わった **Bluetooth Low Energy（LE）** は、正反対の発想から生まれました。この章では、その発想を押さえてから、LE の細部に入っていきます。

## 18.1 なぜ電池が長持ちするのか

LE の設計を貫く目標は、**小さな電池で何か月も何年も動くこと**です。その秘密は意外に単純で、次の一言につきます。

<div class="formula">無線は、できるだけ使わない</div>

小さな機器の中で、電力を一番食うのは無線回路です。電波を出しているときも、受信のために耳を澄ませているときも、数ミリアンペアの電流が流れます。逆に、無線を切って眠っているときの電流はその数千分の1にすぎません。そこで LE は、**ほとんどの時間を眠って過ごし、一瞬だけ起きて通信する**ように作られています。

計算してみましょう。数字はだいたいの値です。

コイン電池 CR2032 の容量は約 225 mAh です。これは「225 mA なら1時間、1 mA なら225時間もつ」という意味です。無線を動かすのに 7 mA 必要だとすると、つけっぱなしなら

<div class="formula">225 mAh ÷ 7 mA ≒ 32 時間</div>

で電池が尽きます。ところが、1秒に1回、3ミリ秒だけ起きて通信するとしたらどうでしょう。動いている時間の割合は 0.3% ですから、平均の電流は 7 mA の 0.3%、つまり 0.021 mA です。眠っているときの電流を 0.002 mA として足すと、およそ 0.023 mA。すると

<div class="formula">225 mAh ÷ 0.023 mA ≒ 9800 時間 ≒ 1年あまり</div>

同じ電池が、**32時間から1年あまりに延びました**。この「動いている時間の割合」を**デューティ比**といいます。この先の章には、デューティ比を下げるための工夫が何度も登場します。

もうひとつの工夫が**役割の非対称**です。LE では、大きな電池を持つスマートフォンのような機器に手間のかかる仕事を任せ、小さな電池の機器はなるべく楽をできるように設計されています。

その違いがよく表れているのが、相手を探す方法です。Classic では、探す側が周波数を変えながら叫び続け、探される側はときどき耳を澄ましていました（第8章）。LE は**役割が逆**です。見つけてほしい小さな機器が短い合図をときどき出し、耳を澄ませ続けるのはスマートフォンの役目です（第21章）。チャネルを3本に絞ることで、「聞き続ける」だけで見つけられるようにしています。

## 18.2 通信スタイルを4つの軸で整理する

LE は1対1で話すだけの技術ではありません。通信のしかたを選べるのが大きな特徴です。ここでは次の4つの軸で整理します。

| 軸 | 選択肢 | 説明 |
|---|---|---|
| 接続 | あり／なし | 相手と約束を交わしてから話すか、一方的に発信するか |
| 相手の数 | 1対1／1対多 | 特定の相手か、受信できる全員か |
| 方向 | 双方向／一方向 | 返事ができるか |
| 時間の制約 | あり／なし | 「この時刻までに届かないと意味がない」データか |

**接続あり**の通信は、2台が約束を交わしたうえで、決めた時刻に交互に話す方式です。相手に届いたかどうかを確認できるので確実です（第22章）。

**接続なし**の通信は、一方的に電波を出して、聞こえた機器が受け取る方式です。受信機の数に上限がないのが強みで、相手を探すための合図にも使われます（第21章、第23章）。Classic にも接続なしの放送（CPB）はありましたが（第11章）、LE ではこちらが主役の1つです。

**時間に縛られた通信**は「アイソクロナス通信」と呼ばれ、音声のように遅れて届いても意味がないデータのためにあります。これは接続ありの形でも、放送の形でも使えます（第24章）。Classic の SCO や eSCO と同じ目的を、別のしくみで実現しています。

さらに LE には、通信以外の能力として、**電波が来た方向を調べる機能**（Direction Finding）と、**相手までの距離を測る機能**（Channel Sounding）もあります（第25章）。

::: bio
放送型の通信はフェロモンや細菌のクオラムセンシングに似ています。出す側は誰が受け取るかを気にせず放出し、受容体を持つ個体だけが反応します。受領確認も返ってきません。一方、接続型の通信は決まった相手とやり取りするシナプスに近いイメージです。
:::

## 18.3 心拍計とスマートフォン

第III部と第IV部では、第1章のランナーが胸につける心拍計と、その値を表示するスマートフォンのアプリを、繰り返し例に使います。先に全体の流れを見ておきましょう。今はわからない言葉があっても大丈夫です。

1. 心拍計が「ここにいます」という短い信号を出し続ける（アドバタイズ）
2. スマホがそれを聞き取り、接続を申し込む
3. 接続すると、約束した間隔で無線を起こして通信する
4. スマホは「あなたは何ができる機器ですか」と問い合わせる
5. スマホは「心拍数が変わったら教えて」と登録する
6. 心拍計は1秒ごとくらいに、心拍数を小さなパケットで送る

このたった6行の裏側で何が起きているのかを、順に明らかにしていきます。第32章では同じ流れを、すべての層を通して見直します。

第III部と第IV部は、Bluetooth SIG の解説文書 LE Primer（原本）を骨組みの参考にしています。原本は Core 6.0 までの内容を扱っています。本書は Core 7.0 と照合し、6.1 以降の機能は関係する章で短く触れるにとどめました。
:::

## まとめ

- LE の低消費電力の基本は「無線をほとんど使わない」こと。デューティ比を下げれば、同じ電池でも桁違いに長くもつ
- 電力に余裕のある機器が手間のかかる役目を引き受ける、非対称な設計になっている。相手を探すときの役割は Classic と逆である
- 接続の有無、相手の数、方向、時間制約の組み合わせで、さまざまな通信スタイルを選べる

## 確認問題

1. Classic の Active な Peripheral と比べて、LE の機器が電池を節約できる一番の理由は何でしょうか。
2. 18.1節の計算で、1秒に1回ではなく10秒に1回だけ3ミリ秒起きるとします。無線の平均電流はいくらになるでしょうか。
3. 空港で、案内放送を多くの人のイヤホンに同時に届けたいとします。4つの軸ではどの組み合わせになるでしょうか。

::: details 答え
1. 無線を動かす時間がずっと短いからです。Classic の Active な Peripheral は呼ばれるかもしれないスロットを毎回聞きますが、LE の機器はほとんどの時間を眠り、約束した時刻やときどきの合図のときだけ起きます。
2. 動いている割合は 3 ms ÷ 10000 ms = 0.03% です。7 mA × 0.0003 = 0.0021 mA となります。ここまで下げると、眠っているときの電流 0.002 mA とほぼ同じ大きさになり、無視できなくなります。
3. 接続なし、1対多、一方向、時間制約あり、です。第24章の BIS がこれにあたります。
:::
