## 2.1 なぜ仕様書が重要なのか

メーカーの違うスマホと心拍計がつながるのは、どちらも同じ約束を守っているからです。その約束を文書にしたものが仕様書で、管理しているのが業界団体の **Bluetooth SIG**（Special Interest Group）です。

Bluetooth の仕様書は1冊ではなく、役割の違う何種類かに分かれています。この章で地図を手に入れておくと、この先の話も、将来仕様書を自分で調べるときも、ずっと楽になります。

## 2.2 コア仕様：Bluetooth そのものの定義

**Bluetooth Core Specification**（コア仕様）は、すべての土台になる最重要の文書です。Bluetooth 全体の構造、各機能、手順、機器どうしが交わすプロトコルを定義していて、LE も Classic も同じ文書に書かれています。

ページ数は数千にのぼるので、最初から順に読む人はまずいません。「Core 5.4」「Core 6.0」のような呼び方の数字は、この文書の版を指しています。

## 2.3 プロファイルとサービス：使い方の約束

コア仕様は「どう通信するか」を決めますが、「心拍数をどのデータ形式で送るか」までは決めていません。そこを決めるのが**プロファイル仕様**と**サービス仕様**です。

説明の前に、ひとつだけ第14章の内容を先取りします。LE の接続では多くの場合、データを持っている機器（**サーバ**）と、それを利用する機器（**クライアント**）という関係ができます。

例として「キーホルダー型の探し物タグ」を考えましょう。スマートウォッチのボタンを押すと、タグが大きな音を鳴らすというものです。タグがサーバ、ウォッチがクライアントです。

**サービス仕様**はサーバの側に注目します。タグが持つべきデータの項目と、値に応じたふるまいを定義します。この例で使われる Immediate Alert Service は、「警告レベル」という項目を持ち、その値が書き込まれたらレベルに応じて音を鳴らすことを定めています。1つのサービス仕様は、機器の能力の1つの側面だけを定義します。

**プロファイル仕様**は登場人物全体に注目します。誰がどの役を演じ、クライアントはどのデータをどう扱うべきかを定めます。この例の Find Me Profile は、探す側と探される側という2つの役を定義しています。

::: analogy
エアコンにたとえてみましょう。サービス仕様は「本体にこの温度設定の項目があり、値が変わると本体はこう動く」という、本体側の仕様書です。プロファイル仕様は「リモコン役と本体役がいて、リモコンはこの項目をこう操作する」という、使い方の取り決めです。
:::

なお、プロファイル仕様とサービス仕様に載っていない製品を作ってはいけないわけではありません。メーカーは独自のサービスを自由に定義できます（第14章）。ただし、独自の形式で話す機器とつながるのは、その形式を知っているアプリだけになります。

## 2.4 プロトコル仕様

応用によっては、コア仕様の手順だけでは足りず、専用のプロトコルが必要になることがあります。その場合は**プロトコル仕様**が別に作られます。代表例が Bluetooth Mesh です。本書では扱いません。

## 2.5 Assigned Numbers：番号の台帳

LE の世界では、データの種類や会社名を番号で表します。たとえば「心拍サービス」は `0x180D` という番号で表され、世界中のどの心拍計でも同じです。こうした番号を割り当てて公開している台帳が **Assigned Numbers** です。

ここで注意したいのは、この番号が表すのは**種類**であって、**個体**ではないことです。`0x180D` は「この機器は心拍サービスを持っている」という意味であって、「この心拍計そのもの」を指しているわけではありません。

::: bio
種類を表す番号は、遺伝子名やアクセッション番号に似ています。ヒトでもマウスでも、同じ遺伝子には同じ名前がつき、1個体を識別するものではありません。第13章では、これと対になる「個体の中での場所を指す番号」が出てきます。
:::

::: se
データの型を表すクラス名やスキーマ名のようなものです。インスタンス ID ではありません。
:::

## 2.6 どの文書を見ればいいか

| 知りたいこと | 見る文書 |
|---|---|
| パケットの形式、接続の手順 | コア仕様 |
| 心拍数のデータ形式 | サービス仕様（Heart Rate Service） |
| 心拍計とスマホの役割分担 | プロファイル仕様（Heart Rate Profile） |
| この `0x....` は何の番号か | Assigned Numbers |
| アドバタイズのデータ項目の定義 | Core Specification Supplement（第15章） |

いずれも [Bluetooth SIG の仕様書ページ](https://www.bluetooth.com/specifications/specs/)から読めます。

::: primer
- **§4 The Bluetooth LE specifications**：仕様書の種類の説明。本章の内容に対応します
- **§18 Additional resources**：仕様書と学習資料の一覧。本書では第17章で紹介します
:::

## まとめ

- すべての土台はコア仕様で、Bluetooth がどう動くかを定義している
- サービス仕様はサーバが持つデータとふるまいを、プロファイル仕様は役割と使い方を定義する
- Assigned Numbers は番号の台帳で、番号が指すのは個体ではなく種類である

## 確認問題

1. 体重計のメーカーが「体重のデータ形式」を調べたいとき、まず見るべきなのはコア仕様でしょうか、それとも別の文書でしょうか。
2. 街中の2台の心拍計は、同じサービス番号 `0x180D` を持っています。これは2台を区別するのに使えるでしょうか。
3. プロファイル仕様とサービス仕様の違いを一言ずつで説明してください。

::: details 答え
1. サービス仕様です（Weight Scale Service など）。コア仕様は通信方法を定義する文書で、体重の形式は定めていません。
2. 使えません。番号は「心拍サービスという種類」を表すだけです。個々の機器の区別には、第16章で扱う機器アドレスなどを使います。
3. サービス仕様は「サーバが何を持ち、どうふるまうか」、プロファイル仕様は「誰がどの役で、どう使うか」です。
:::
