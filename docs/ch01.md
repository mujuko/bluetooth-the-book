# 第1章 Bluetooth とは何か

::: goal
- Bluetooth に2つの方式があることと、それぞれの得意なことを説明できる
- 2つの方式が生まれた順番と、その後の歩みを年表でたどれる
- 本書を貫く例で、どの機器がどちらの方式を使うかを言える
:::

## 1.1 2つの Bluetooth

Bluetooth という名前の下には、実は2つの異なる無線方式があります。

ひとつは2000年ごろから製品に載り始めた**昔ながらの Bluetooth** です。正式な名前は **BR/EDR** で、BR は Basic Rate、EDR は Enhanced Data Rate の略です。最初の BR の速さは 1 Mb/s で、のちに速くした EDR が加わりました。**Bluetooth Classic** という通称も広く使われていますが、Core 仕様の Architecture 編には一度も出てきません。本書では読みやすさを優先して Classic と書き、仕様の話をするときは BR/EDR と書きます。

もうひとつが、2010年の仕様 Bluetooth Core 4.0 で登場した **Bluetooth Low Energy（LE）** です。BLE と書かれることも多いのですが、本書では公式の表記にならって LE と呼びます。

大事なのは、LE は Classic の「新しい版」ではないということです。両者は別の方式として並んで存在していて、Classic しか話せない機器と LE しか話せない機器は、直接は通信できません。スマートフォンのように両方を載せた機器もあり、相手に応じて使い分けています。

| | Bluetooth Classic（BR/EDR） | Bluetooth LE |
|---|---|---|
| 登場 | 2000年ごろから製品化 | 2010年（Core 4.0） |
| 得意なこと | 連続した大きめのデータを2台で流す | 小さなデータをときどき送る、広く放送する |
| つながり方 | 2台の直接通信が中心 | 1対1に加えて、1対多の放送もある |
| 電源のイメージ | 充電式のバッテリー | コイン電池でも長期間 |
| 代表例 | 従来のワイヤレスイヤホン、カーオーディオ、キーボード | 心拍計、紛失防止タグ、電子棚札、LE Audio 対応の補聴器 |

ただし、表の「得意なこと」は、もともとの設計の話です。LE はその後、データの多い用途にも手を広げていて、Core 7.0 では最大 7.5 Mb/s の HDT PHY も加わりました（第19章）。「Classic は速く、LE は遅い」とは、もう言い切れません。

::: extra 名前の由来
Bluetooth という名前は、10世紀にデンマークを統一した王ハーラル・ブロタン（Harald Bluetooth、「青歯王」）に由来します。さまざまな機器を1つの規格で束ねる、という願いが込められています。
:::

## 1.2 2つの発想

2つの方式の違いは、生まれたときの目的の違いから来ています。

Classic は、機器をつなぐ**ケーブルを置き換える**ために作られました。この出発点が Classic の性格を決めています。2台の機器のあいだに**見えない電線を1本張り、接続している間はそこにデータが流れ続ける**という発想です。

LE の目標は、**小さな電池で何か月も何年も動くこと**でした。そのために、ほとんどの時間は無線を止めて眠り、用があるときだけ一瞬起きて短く話します（第18章）。

なぜ Classic を改良せず、別の方式を作ったのでしょうか。Classic では、接続している Peripheral は呼ばれるかもしれない時間を毎回聞き（第6章）、相手を探す側は周波数を変えながら叫び続けます（第8章）。どちらも、無線を動かし続けることを前提にした土台です。手直しだけで、何年も電池がもつほど眠らせるのは難しかったのです。そこで LE は、BR/EDR より消費電流が少なく、単純で安い機器を作れるように、土台から設計し直されました。その代わり、2つの方式は直接は話せなくなりました。

::: analogy 電話と手紙
Classic は電話に似ています。一度つなぐと回線を握ったままで、いつでも話せます。ただし、つないでいる間はお互いに受話器を耳に当てていなければなりません。

LE は手紙に似ています。普段は何もせず、用があるときだけ短い便りを出します。

どちらが優れているという話ではありません。長い話を途切れずにするなら電話、たまに短い用件を伝えるなら手紙が向いています。
:::

それでも今、音声やデータを流し続ける製品に Classic が多く使われているのは、**長年の互換性**があり、機器の組み合わせを選ばずにつながるからです。

## 1.3 Bluetooth の歩み

2つの方式の歩みを、Core 仕様の変更履歴でたどってみます。年は SIG が仕様を採択した年です。詳しい機能は各章で説明します。

| 版 | 年 | Classic に関するおもな変更 | LE に関するおもな追加 |
|---|---|---|---|
| 1.2 | 2003 | 適応ホッピング（AFH）、eSCO | ― |
| 2.0 + EDR | 2004 | EDR（2 Mb/s、3 Mb/s） | ― |
| 2.1 + EDR | 2007 | Secure Simple Pairing、EIR、Sniff サブレーティング | ― |
| 3.0 + HS | 2009 | L2CAP の新しいモード、拡張された電力制御。Wi-Fi の無線を借りる高速化（HS） | ― |
| 4.0 | 2010 | ― | LE の誕生 |
| 4.1 | 2013 | Secure Connections、CPB、時計の調整など | L2CAP の接続指向チャネルなど |
| 4.2 | 2014 | ― | LE Secure Connections、データ長の拡張、リンク層でのプライバシー |
| 5.0 | 2016 | Slot Availability Mask、Park の削除 | 2M と Coded の PHY、拡張アドバタイズ、チャネル選択アルゴリズム #2 |
| 5.1 | 2019 | ― | Direction Finding、GATT のキャッシュ、定期アドバタイズの同期の引き渡し |
| 5.2 | 2019 | ― | アイソクロナス通信、EATT、送信電力制御 |
| 5.3 | 2021 | 3.0 の HS の削除 | 接続のサブレーティング |
| 5.4 | 2023 | ― | PAwR、暗号化アドバタイズ |
| 6.0 | 2024 | ― | Channel Sounding、判断ベースのフィルタ、広告主の監視 |
| 6.1 | 2025 | ― | アドレス更新間隔のランダム化 |
| 6.2 | 2025 | ― | より短い接続間隔 |
| 6.3 | 2026 | ― | Channel Sounding の改良。データ署名の廃止 |
| 7.0 | 2026 | ― | HDT PHY（最大 7.5 Mb/s）、アイソクロナス通信のパラメータ更新 |

Core 5 以降の新機能の多くは LE 向けです。Classic は成熟した技術として、大きくは変わらず使われ続けています。2025年からは年2回のペースで更新されているので、最新の版は SIG のサイトで確認してください。本書は 2026年11月に採択された Core 7.0 に基づいています。

## まとめ

- Bluetooth には Classic（BR/EDR）と LE の2系統があり、別の方式として並んでいる。両方を載せた機器は、どちらの相手とも話せる
- Classic はケーブルの代わりとして、つないでいる間データを流し続ける発想で作られた
- LE は小さな電池で長く動くことを目指して、2010年の Core 4.0 で加わった
- 本書は、走りながら音楽を聴くランナーのスマホ、ヘッドホン、心拍計を例に進む

## 確認問題

1. 「Bluetooth LE は Classic の新しい版だ」という説明はどこが正しくないでしょうか。
2. BR/EDR のみの機器と LE のみの機器は通信できるでしょうか。スマートフォンがどちらとも話せるのはなぜでしょうか。
3. ランナーの例で、ヘッドホンが Classic を、心拍計が LE を使うのはなぜでしょうか。データの性質から考えてください。

::: details 答え
1. LE は Classic を置き換える新版ではなく、別の方式です。Classic だけの機器と LE だけの機器は直接通信できません。
2. 通信できません。別の方式だからです。スマートフォンの多くは両方を載せたコントローラを持っているので、相手に合わせて使い分けられます。
3. ヘッドホンは音楽を途切れなく流し続けるので、つないでいる間データを流す Classic が向いています（対応する機器が多いことも理由です）。心拍計は1秒に1回、数バイトを送るだけなので、ほとんど眠っていられる LE が向いています。
:::
