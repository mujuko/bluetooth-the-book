# 第5章 リンク層の基本

::: goal
- パケットの各部分の役割を説明できる
- CRC が何を検出し、何ができないかを説明できる
- リンク層の状態の遷移と、セントラルとペリフェラルの決まり方を説明できる
- 6つの「通信の型」を比較できる
:::

物理層は、ビットを電波にするところまでが仕事でした。「どのチャネルで、いつ、どんな形のデータを送るか」を決めるのが**リンク層**です。

リンク層は LE の中で最も複雑な部分で、LE の多彩な使い方はほとんどここで生み出されています。そのため本書でも第5章から第9章までを使って説明します。この章では共通の基本を押さえます。

## 5.1 パケットの形

リンク層が送るひとまとまりのデータを**パケット**といいます。1M と 2M の PHY で使うパケットの形を図5-1 に示します。

順番に見ていきましょう。

**プリアンブル（Preamble）** は、0 と 1 が交互に並んだ決まったパターンです。データではなく、受信機が準備を整えるためのものです。受信機はこの部分で周波数を合わせ、信号の強さに合わせて増幅率を調整し、1シンボルの区切りのタイミングをつかみます。

::: analogy
ラジオのチューニングのつまみを合わせ、音量を調節し、話し手のリズムをつかむ。本題に入る前の、ほんの一瞬の準備です。
:::

**アクセスアドレス（Access Address）** は、「このパケットは誰たちの会話か」を示す札です。受信機はここを見て、背景の雑音と本物のパケットを区別し、関係ないパケットならすぐに受信をやめて眠ります。接続中の2台は、接続のときにランダムに決めたアドレスを共有します。一方、アドバタイズのパケットは、すべての機器が同じ `0x8E89BED6` を使います。誰でも受け取れるようにするためです（例外は第8章の定期アドバタイズで、こちらは列ごとにランダムなアドレスを使います）。

**PDU** が中身の本体です。どんな内容が入るかは、後の章で見るように使い方によって変わります。暗号化されているときは、PDU の末尾に改ざんを検出するための **MIC**（Message Integrity Check、4バイト）も加わります。

**CRC**（巡回冗長検査）は、途中でビットが化けなかったかを調べるための検算の値です。

**CTE**（Constant Tone Extension）は、方向探知を使うときだけ付きます（第10章）。

## 5.2 CRC：化けたことに気づくしくみ

電波は雑音の影響を受けるので、1 が 0 に化けることは普通に起こります。そこで送信側は、パケットの内容から 3 バイトの値を計算して末尾につけます。受信側も同じ計算をして、一致すれば正しいと判断します。

CRC はあくまで**誤りを検出する**ためのもので、誤りを直す力はありません。誤りが見つかったらそのパケットは捨てて、送り直してもらいます。接続している場合の再送のしくみは第7章で説明します。

::: analogy
買い物の合計を二人で別々に計算して照らし合わせるようなものです。合わなければどこかが間違っていると分かりますが、どこが間違っているかまでは分かりません。
:::

::: se
ハッシュやチェックサムの仲間です。ただし CRC は偶然の誤りを見つけるためのもので、悪意のある改ざんは防げません。改ざん対策は暗号技術を使った MIC の役割です。
:::

なお、PDU と CRC は送信前に**ホワイトニング**という処理で攪拌されます。0 や 1 が長く連続すると受信機の周波数の追従がずれてしまうので、ビットの並びをランダムに近づけて、受信側で元に戻します。

## 5.4 セントラルとペリフェラル

ここでとても大切な言葉が登場します。接続した2台には、役割の名前がつきます。

- **セントラル**：接続を申し込んだ側（イニシエート状態から来た機器）
- **ペリフェラル**：申し込みを受けた側（アドバタイズ状態から来た機器）

心拍計とスマホなら、ふつうはスマホがセントラル、心拍計がペリフェラルです。第1章の「非対称な設計」のとおり、接続のタイミングを決めるなど主導権を握るのがセントラルです。

::: extra 古い呼び名
古い資料では、セントラルを Master、ペリフェラルを Slave と書いていることがあります。Core 5.3 で用語が改められました。次の節に出てくる Filter Accept List も、以前は White List と呼ばれていました。
:::

## 5.5 チャネルの使い分けとフィルタ

**チャネルの使い分け**　同じチャネルを使い続けると、そこに雑音や他の機器の電波があったときに通信がずっと失敗します。そこで LE は、時間とともに複数のチャネルに分散して通信します。代表が接続中に使う**適応型周波数ホッピング**で、第7章で詳しく見ます。

**フィルタポリシー**　リンク層は、受信したパケットのうち不要なものを自分で捨て、上の層に渡さないようにできます。受け入れる機器のアドレスを **Filter Accept List** に登録しておけば、たとえば「登録済みの機器のアドバタイズだけを報告する」「登録済みの機器からの接続だけを受ける」といった動作ができます。ホストが起きて処理する回数が減るので、電力の節約にもなります。

## 5.6 6つの通信の型

リンク層が用意する通信の型を**論理トランスポート**といいます。第II部の残りの章は、これらを順に見ていく旅です。先に全体を見渡しておきましょう。

| 型 | 接続 | 相手 | 方向 | 受信確認 | 例 | 章 |
|---|---|---|---|---|---|---|
| **LE-ACL** | あり | 1対1 | 双方向 | あり | 心拍計とスマホ | 第7章 |
| **ADVB** | なし | 1対多 | 一方向 ※ | なし | 機器の発見、ビーコン | 第6章 |
| **PADVB** | なし | 1対多 | 一方向 | なし | 決まった周期の放送 | 第8章 |
| **PAwR** | なし | 1対多 | 双方向 | 返事の枠あり | 電子棚札 | 第8章 |
| **LE-CIS** | あり | 1対1 | 双方向 | あり | イヤホンで通話 | 第9章 |
| **LE-BIS** | なし | 1対多 | 一方向 | なし | 公共の音声放送 | 第9章 |

※ データの本体は一方向ですが、受信側が「もっと情報を」「接続したい」と短く返すことはできます。

::: deep トランスポートのさらに下の構造
コア仕様は、この型を4段の階層で定義しています。**物理チャネル**（電波の使い方の種類：40本の使い方のパターン）、**物理リンク**（1本の物理チャネルの上のつながり）、**論理トランスポート**（上の表の型）、**論理リンク**（制御用とユーザーデータ用の区別）です。

たとえば心拍計の通信は、「接続用の物理チャネル（37本でホッピング）の上に、LE-ACL という型があり、その上の LE-U というリンクでデータを流す」と説明されます。道路の種類の上に運行ルールがあり、その上を旅客便と業務便が走っている、というイメージです。仕様書を読むときに出会う言葉なので、名前だけ覚えておくと役立ちます。
:::

::: primer
- **§7.2**：Coded PHY 用のパケットの形。FEC エンコーダとパターンマッパの処理
- **§7.3**：状態と役割の許される組み合わせについての言及
- **§7.5**：状態ごとのフィルタポリシーとモードの考え方。判断ベースの高度なフィルタ（本書では第6章）
- **§7.7**：物理チャネル、物理リンク、論理リンク、論理トランスポートの定義と組み合わせ（LE-C, LE-U, ADVB-C, ADVB-U など）
:::

## まとめ

- パケットはプリアンブル、アクセスアドレス、PDU、CRC（と必要なら CTE）からなる
- CRC は誤りの検出だけを行い、修正はしない
- リンク層はスタンバイを中心とした状態マシンで動く。申し込んだ側がセントラル、受けた側がペリフェラルになる
- 通信の型には ACL、ADVB、PADVB、PAwR、CIS、BIS がある

## 確認問題

1. アクセスアドレスがあると、受信機の電力の節約になるのはなぜでしょうか。
2. CRC が一致しないパケットを受け取ったとき、受信機はそのパケットを直せますか。
3. スマホと心拍計が接続しました。どちらがセントラルかは何で決まりますか。「スマホだから」が答えではありません。

::: details 答え
1. パケットの先頭近くで自分に関係ないと分かれば、残りを受信せずに無線を止められるからです。
2. 直せません。CRC は誤りの有無を調べるだけです。捨てて再送してもらいます。誤りの訂正ができるのは Coded PHY の FEC です。
3. 接続を申し込んだ側（イニシエート状態からコネクション状態に移った機器）がセントラルになります。スマホがペリフェラルになることも、仕様上は可能です。
:::
