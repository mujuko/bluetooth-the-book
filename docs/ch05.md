# 第5章 HCI：ホストとチップの窓口

::: goal
- HCI のコマンド、イベント、データの役割を説明できる
- HCI のやり取りを、周りの機器を探す例で追える
- 自分の環境で HCI の通信を観察する方法を知る
:::

第I部の最後に、ホストとコントローラをつなぐ **HCI**（Host Controller Interface）を見ておきます。Classic でも LE でも使う、共通の窓口です。

## 5.1 HCI の役割

第3章で見たように、ホストとコントローラは別のメーカーが作ることがあります。それでもつながるのは、やり取りの方法が HCI で標準化されているからです。HCI は Classic にも LE にも共通です。

やり取りされるのは3種類です。

| 種類 | 向き | 内容 |
|---|---|---|
| **コマンド** | ホスト → コントローラ | 「周りの機器を探して」などの命令 |
| **イベント** | コントローラ → ホスト | コマンドの結果や、「機器が見つかった」などの通知 |
| **データ** | 両方向 | 接続で運ぶデータや音声データ |

イベントには、コマンドへの返事として返るものと、コントローラの都合で突然届くもの（見つけた機器の報告など）があります。

::: se
ドライバの API とほとんど同じ形です。コマンドが API 呼び出しで、イベントが戻り値とコールバックにあたります。ホストは無線のタイミングを制御せず、「こういう設定で動いて」と頼むだけです。
:::

ポイントは、呼びかけをどの周波数で何回送るかといった判断が、ホストまで上がっていないことです。電波のマイクロ秒単位のやり取りはコントローラの中で完結します。ホストはコマンドを1つ送り、結果の報告を受け取るだけです。第3章の脊髄反射のたとえそのままです。

LE で周りの機器を探すときも同じです。ホストはスキャンの設定と開始を命じるだけで、受信した内容はコントローラがまとめて報告します（第21章）。

## 5.3 物理的なつなぎ方

HCI の機能的な定義（どんなコマンドがあるか）は、物理的な線の種類とは切り離されています。実際の線としては次の4種類が定義されています。

| トランスポート | 使われ方の例 |
|---|---|
| UART | 同じ基板の上のチップ間の接続 |
| USB | パソコンに挿す USB ドングル |
| Secure Digital（SD） | SD カードのインタフェース経由 |
| 3線式 UART | 信頼性確保の手順を含む3線の UART |

ホストとコントローラが1つのチップに入っているなら、HCI は単なる内部の関数呼び出しになっていることも、そもそも省略されていることもあります。

::: extra HCI を覗いてみよう
HCI は、Bluetooth の動きを観察する最高の窓です。アプリと無線の間を流れるやり取りが、そのまま読めるからです。

- **Linux**：`btmon` コマンドで、リアルタイムに HCI の通信が見られる
- **Android**：開発者向けオプションの「Bluetooth HCI スヌープログ」を有効にすると記録できる。保存したログは Wireshark で開ける

アプリが思うように動かないときは、まずここを見ると原因が絞りやすくなります。
:::

::: primer
- **§10.3**：各トランスポートの詳細（UART の設定、USB のエンドポイント、SD 協会の文書との関係、3線式 UART の手順）
- **§10.4.1**：方向探知の信号を送るための HCI の設定の例
- **§10.4.2**：経路損失の監視（送信電力制御の機能の一部）を設定する例
:::

## まとめ

- HCI はホストとコントローラの標準の窓口で、コマンド、イベント、データをやり取りする
- 時間に厳しい電波のやり取りはコントローラの中で完結し、ホストは設定と結果の受け取りを担当する
- 物理的な線の種類は複数あるが、機能の定義は共通である

## 確認問題

1. スマホのアプリが「機器を探す」を指示してから一覧が表示されるまでに、HCI を通るのはどんなメッセージでしょうか。
2. 相手の機器が電波で送ってきた返事のパケットは、そのままの形で HCI を通るでしょうか。
3. 同じ OS のドライバが、メーカーの違う無線チップを動かせるのはなぜでしょうか。

::: details 答え
1. ホストからの `HCI_Inquiry` のコマンド、受け付けたことを伝えるイベント、見つけた機器の報告のイベント、探し終わったことを伝えるイベントです。
2. そのままの形では通りません。コントローラが受信し、必要な内容を Extended Inquiry Result などのイベントにまとめてホストへ報告します。
3. どのチップも同じ HCI のコマンドとイベントに対応しているからです（メーカー独自の拡張コマンドはありますが、基本機能は共通です）。
:::
